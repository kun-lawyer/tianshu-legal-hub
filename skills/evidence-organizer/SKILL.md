> **工作纪律**：复核须知封面、来源标签、🔴🟠🟡🟢 风险刻度、决策树收尾、引用纪律均按本文执行。文中"守则 A3""E10"等编号沿用作者内部守则的条目号，含义已就地写明。
>
> 如果你配置了自己的共享守则（如 legal-shared-guardrails）、执业档案或客户档案，启动时先读，冲突时以你的守则为准；没有就直接按本文做。

# 证据整理

按中国法院和仲裁机构标准格式，编制证据目录、整理质证意见、将证据与争议焦点关联。

## 出稿前置检查

1. **当事人立场**：原告 / 被告 / 第三人
2. **争议焦点**：已明确就直接套；未明确建议先跑 case-analyzer 的 analyze 模式
3. **披露材料提醒**：处理来自对方在另案中披露的证据时，**提醒跨案使用可能违反保密义务**，别拿 A 案的对方书证打 B 案
4. **大输入协议**：证据超 50 份时分批处理

## 工作流程

### 1. 收集信息

- 案件基本信息：案号、当事人、案由
- 当事人立场：原告 / 被告 / 第三人（申请人 / 被申请人）
- 证据材料清单：所有拟提交或已收到的证据
- 争议焦点（如已明确）

### 2. 编制证据目录

#### 举证证据目录（我方提交）

```markdown
# 证据目录

案号：（2026）X01民初1号
举证方：原告 / 被告 XXX

| 序号 | 证据名称 | 证据形式 | 页数 | 证明目的 | 证据强度 |
|---|---|---|---|---|---|
| 证据一 | 《建设工程施工合同》 | 原件 | 1 至 45 | 证明合同关系成立 | 🔴 单一直接 |
| 证据二 | 工程竣工验收报告 | 原件 | 46 至 48 | 证明工程已验收 | 🔴 单一直接 |
| 证据三 | 工程结算书 | 复印件 | 49 至 52 | 证明结算金额 | 🟡 旁证组合（需配合证据五） |
| 证据四 | 现场照片 | 电子数据 | 53 至 56 | 证明施工质量 | 🟢 背景 |
```

### 3. 证据强度三档（守则 A3 + E10）

| 等级 | 含义 | 何时用 |
|---|---|---|
| 🔴 **单一直接** | 单凭这一份就能证明待证事实 | 合同原件、签字盖章件、判决书 |
| 🟡 **旁证组合** | 单份不能证明，需与其他证据组合 | 单独的转账记录、不完整的电子聊天 |
| 🟢 **背景** | 仅作背景或补强 | 现场照片、行业报告 |

**注意**：旧版"高/中/低"已废弃。

### 4. 质证意见（对方证据）

对方证据含电子数据、证人证言、鉴定意见，或处于二审、再审的，先读 `references/特殊证据质证清单.md` 找切入点。下表是内部梳理格式；对外质证意见如配置了自己的质证意见模板就按模板写，没有就按"对证据几（名称）的质证意见 + 真实性、合法性、关联性、证明力中真正有争议的那几项"逐份写成段落，不照下表机械铺满三性。

```markdown
# 质证意见

案号：（2026）X01民初1号
质证方：被告 XXX

| 序号 | 对方证据 | 真实性 | 合法性 | 关联性 | 证明力 | 质证意见 |
|---|---|---|---|---|---|---|
| 证据一 | XXX | 认可 / 不认可 | 认可 / 不认可 | 认可 / 不认可 | 强 / 弱 | [具体质证意见] |
```

### 5. 证据-争议焦点关联

```markdown
# 证据-争议焦点关联表

## 争议焦点一：[焦点描述]

### 我方证据
| 证据 | 证明内容 | 证据强度 | 证明力评估 |
|---|---|---|---|
| 证据 X | ... | 🔴 / 🟡 / 🟢 | 强 / 中 / 弱 |

### 对方证据
| 证据 | 对方主张 | 我方质证要点 |
|---|---|---|

### 小结
[该焦点的证据分析结论 + 缺口提示]
```

### 6. 证据链完整性检查

```markdown
# 证据链检查报告

## 证据链完整性
| 待证事实 | 已有证据 | 证据充分性 | 补充建议 |
|---|---|---|---|
| 合同关系 | 合同原件 | 充分 🟢 | 无 |
| 实际损失 | 暂无 | 不足 🔴 | 建议申请鉴定 / 补充 X 证据 |

## 证据风险提示
- [列出证据缺口和潜在风险]

## 补充取证建议
- [需要补充的证据及获取方式]
```

### 7. 决策树（守则 A4）

```
> **接下来怎么走？请选一个：**
> 1. **整理标准化目录 docx**：我按法院标准格式导出 .docx，准备提交。
> 2. **取证强化**：我列出缺口和取证路径。
> 3. **质证准备**：我按对方证据起草庭前质证提纲。
> 4. **申请鉴定 / 调取**：我起草鉴定申请书 / 调取证据申请书。
> 5. **其他**
```

### 8. 清单外一问（守则 A5）

```
> **清单没问到、但有经验的律师会想到的一件事：** [例：电子证据公证保全做了吗？没做的话对方否认真实性会很被动]
```

## 复核须知封面

```
> ⚠️ 复核须知
> - **来源**：[当事人提供 / 公证保全 / 第三方平台导出]
> - **已读**：证据 N 份（清单：……）
> - **待复核**：N 处证据强度评级需主办律师拍板
> - **披露限制**：[本批材料是否来自另案对方披露？如是请确认跨案使用合法性]
> - **签发前**：核对每份证据的页数、形式、证明目的
```

## 证据形式说明

| 形式 | 说明 |
|---|---|
| 原件 | 文书原件 |
| 复印件 | 需说明原件去向 |
| 照片 | 现场 / 实物 |
| 录音 | 附文字整理稿 |
| 录像 | 录像资料 |
| 电子数据 | 微信 / 邮件 / 短信截图（**建议公证保全**） |
| 鉴定意见 | 司法鉴定报告 |
| 证人证言 | 书面证言（需出庭） |

## 注意事项

- 证据编号连续，不跳号
- 每份证据的证明目的应具体明确，与诉讼请求/争议焦点直接关联
- 区分原件和复印件
- 电子证据注意保全方式（公证 / 区块链存证）
- 质证从三性（真实、合法、关联）+ 证明力展开
- 如需 docx 输出：有 litigation-doc-generator 一类诉讼文书 skill 就用它出质证意见和证据目录；没有就用 python-docx 出 docx（证据目录用表格，列：序号、证据名称、证据来源或形式、页码、证明目的；质证意见按法定格式写正文），再调用 gongwen-format 排版（没有 skill 机制的工具直接读 `skills/gongwen-format/SKILL.md` 照做；纯表格的证据目录可不排版）

## 重要规则

1. **证据强度三档统一**：🔴 单一直接 / 🟡 旁证组合 / 🟢 背景
2. **跨案使用披露材料提醒**：别拿 A 案的打 B 案
3. **复核须知封面**含披露限制行
4. **决策树 + 一问**
5. **电子证据强烈建议公证保全**
