> 如果你配置了执业档案（署名、默认立场）或客户档案（红线条款、签字风格），启动时先读，客户档案偏好覆盖通用默认；没有就按本文执行。

## 操作清单

1. **确定立场** 客户档案有"默认立场"直接套；没有时停下向用户提问"审甲方稿/乙方稿/中立审"
2. **读取材料** 用 python-docx 读合同；有招标文件且合同审查确需比对时，再用 pdfplumber 读取，扫描件用 mineru-ocr 转 Markdown。对方主体信息缺失、矛盾或用户明确要求主体风险核验时才查企业信息（见下文「主体核验」）
3. **形成批注清单** 10 至 20 条，按合同条款顺序排列，只批实质条款
4. **加批注** 先复制 `{合同名}_审核版.docx` 到原文件夹，再调 `scripts/add_comments.py` 对副本加批注，原文不动
5. **汇报** 给出审核版文件路径与批注数量；如有 🔴 项口头提示
6. **临时文件** 脚本中间数据放系统临时目录，不在合同目录创建后再执行清理流程

## 批注格式

每条批注**只写"修改意见"一栏**，给出可操作的具体改法。问题描述可揉入修改意见前半句（"鉴于……建议改为……"），或省略。

**必给具体改法（硬性）**：每条批注必须默认直接写出拟替换/新增的条款文字（用【建议修改为】/【建议新增】引出），金额、比例、份额要按合同金额算成具体数字。禁止只写"建议完善""建议明确""建议协商""可考虑调整"等空泛话而不附可落地条款文本，无需等用户追问。

**风险等级默认关**：批注正文默认不加 🔴🟠🟡🟢 等风险等级标记，除非用户当次明确要求。汇报时仍可口头提示最需关注项。

定位通过 `search_text` 匹配合同原文片段，需保证片段在全文唯一（脚本用 `in` 匹配，重复时只命中第一处）。遇重复文字取上下文更长的片段。

署名取执业档案的 `author` 字段；没有档案时用 comments.json 里的 `author` 或命令行 `--author "张三律师"` 指定。都不给时脚本默认署名"审核律师"，交付前提醒用户改成真实署名。

## 批注覆盖范围

**应批**（实质条款）：
- 争议管辖（按客户档案红线，无档案时按惯例倾向己方所在地）
- 违约责任（双方对等、违约金幅度、损失含合理维权费用）
- 付款条件（预付比例、节点、收款保障）
- 合作期限（自动续期警惕、终止通知期、保留无理由提前终止权）
- 排他性条款（长期独家锁定 + 反垄断风险）
- 关键时限（结算周期、故障恢复、客诉响应、退款审核）
- 质量与验收标准、知产保密、数据合规
- 招标偏离：合同条款实质性偏离招标文件的必批

**不批**（纯填空型留白，业务部门签订前自然补全）：
- 主体登记信息留白
- 双方账户、纳税人识别号、联系人信息留白
- 签约日期留白
- 项目名称纯留白（但项目范围或规模在条款中仍有实质问题的，仍批实质问题）

## 招标偏离对照（有招投标文件时强制）

凡随附招标文件/投标文件，形成批注清单前**先逐项过一遍下表**，把合同条款与招标文件对齐，逐项判"一致／对己方有利偏离／对己方不利偏离"。不利偏离与遗漏项必批；有利偏离也提示一句，并建议锁定、防对方事后援引招标文件原标准反悔。

| 对照项 | 看什么 |
|---|---|
| 工期 / 交付节点 | 合同工期是否短于或长于招标文件；漏掉的节点（如"中标后 N 天提供设计资料"） |
| 质保期 / 使用寿命 | 质保月数、顺延月数；招标文件要求承诺的各部件使用寿命年限是否落地 |
| 违约金幅度与上限 | 逾期、根本违约违约金比例及封顶是否低于招标文件标准 |
| 履约 / 质量保证金 | 招标文件要求的履约保证金（常为合同额 10%）是否在合同中落地，勿与质量保证金混同 |
| 付款比例与触发条件 | 预付比例、收款节点、收款保障是否较招标文件对己方更不利 |
| 验收标准 | 验收依据是否锁定为招标文件技术规格书 + 投标文件技术承诺 |
| 争议管辖 | 是否与招标文件一致、是否倾向己方所在地 |
| 附件效力顺序 | 合同与招投标文件冲突时的适用顺位是否约定，防对方援引较低标准对抗合同 |

## 主体核验

仅在对方主体信息缺失、矛盾，或用户明确要求主体风险核验时，用你可用的企业信息查询渠道（天眼查、企查查、元典企业等的 MCP 或网站，国家企业信用信息公示系统，中国执行信息公开网）核验。当前材料已有完整且一致的登记信息时不重复核验：
- **无风险** 汇报中口头提一句"对方主体核验通过"，不加批注
- **有风险** 在合同前言（搜 "甲    方" 或 "乙    方" 段落）加一条总览批注，列风险事项 + 建议要求对方提供解释或担保

查询用**完整登记名或 18 位统一社会信用代码**，禁用简称直查；只有简称时先检索候选，由用户选定。风险核验至少查失信被执行人、被执行人、严重违法失信三项，能并行就同一批发出；查询结果为空即无记录，不必换渠道重查。批注里注明数据来源和查询日期。

`scripts/` 下的 `workflow.py`、`contract_review.py`、`qcc_mcp_client.py` 等是上游项目直连企查查的旧版完整流程（见 `NOTICE.md` 与 `SKILL_EN.md`），本 skill 的默认流程不调用它们。

## 立场关注点速查

**审甲方稿**（己方为发包/买方/客户方）：

| 重点 | 关注内容 |
|---|---|
| 争议管辖 | 倾向己方所在地管辖或仲裁 |
| 违约责任 | 双方对等、违约金幅度、损失含合理维权费用 |
| 付款 / 结算 | 异议解决不得"以乙方平台数据为准"兜底 |
| 合作期限 | 自动续期警惕；保留无理由提前终止权 |
| 排他性 | 长期独家锁定 + 服务不达标自动失效条件 |
| 验收 | 主动验收期与默认通过条件不得宽于乙方违约救济期 |

**审乙方稿**（己方为承包/卖方/服务方）：

| 重点 | 关注内容 |
|---|---|
| 付款节奏 | 预付比例、收款节点明确、逾期付款利息 |
| 违约金幅度 | 总额不超合同金额 30%，主张过分高于损失抗辩空间 |
| 验收程序 | 验收期不得过短、默认通过条件清晰 |
| 不可抗力 | 范围合理、通知期可操作 |
| 解除权 | 限制甲方任意解除，约定解除补偿 |
| 知识产权 | 区分背景成果与项目成果归属 |

**中立审** 平衡双方风险，重点查条款无效、违法强制性规定、显失公平。

## 输出

- `{合同文件名}_审核版.docx` 带批注的合同副本（与原文件同目录）

不再输出合同概要、综合审核意见、业务流程图。如客户档案明确要求，再另行追加。

## 技术注意

- 依赖：`add_comments.py` 需 `lxml`；上游旧版脚本另需 `requirements.txt` 所列依赖
- 用法：`python -X utf8=1 scripts/add_comments.py "合同_审核版.docx" comments.json --author "张三律师"`，comments.json 格式见脚本开头说明
- 批注脚本 `search_text` 须在合同正文 / 表格中唯一可定位
- 合同文件名含空格时，调脚本路径用双引号包裹
- 构造批注 JSON 时，Python 源码中**用中文双引号**避开与字符串定界符冲突；序列化用 `json.dump(..., ensure_ascii=False)`
- 用 `python -X utf8=1` 运行，避免 Windows 默认 cp936 编码问题
- 脚本会**覆盖输入文件**，务必先复制副本再调脚本

## 客户特化

- **常合作客户** 为每家客户建一份客户档案（默认立场、签字风格、红线条款），审查前先读并套用偏好。档案放哪由你自己定，本 skill 不规定路径
- **需要出法律评审表等配套表格时** 有对应的评审表 skill 就用它；没有就在批注完成后另按客户要求的表格格式整理意见
