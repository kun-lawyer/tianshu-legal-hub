# 应诉一条龙（开案套件）

目标：法院短信进来（或新收一夹案件材料），一次跑完从"下载文书"到"手续齐、案情清、缺口明"的全部开案动作，交付编号成套的文件。

## 第一步：文书获取与归档

- 输入含法院短信或送达链接：**调用 court-sms skill**（没有 skill 机制的工具直接读 `skills/court-sms/SKILL.md` 照做）完成解析、下载、归档，不要自己重写下载逻辑。
- 输入是已有案件文件夹：跳过下载，直接读材料。没有文字层的扫描件先用 mineru-ocr 转 Markdown。
- 归档目录即案件文件夹，后续所有产出放同一文件夹根目录。

## 第二步：提取案件要素

从起诉状、传票、通知书等提取并列表向用户确认：

- 案号、受理法院、审理程序（一审/二审/仲裁/执行）
- 当事人全称及诉讼地位；**涉企业主体用你可用的企业信息查询渠道（天眼查、企查查、国家企业信用信息公示系统等）核验全称、统一社会信用代码、法定代表人**，用完整登记名或信用代码查，不得臆测主体信息
- 案由、诉讼请求及金额
- 关键期限：举证期限、开庭时间、答辩期（从传票/通知书原文提取，⚠️ 高亮提醒）

## 第三步：一次问清（守则 A13/A18，不挤牙膏式反复问）

用一条简洁的普通文本消息集中向用户提问，答案缺失的字段在文书里留 `〔待补：XX〕` 占位，不编造：

1. **代理立场**：代理哪一方（可多个委托人，如"单位 + 个人"双被告）
2. **收费方式**：固定 / 风险 / 基本费加风险费（默认沿用同类案件惯例，金额留占位）
3. **委托人联系人及电话**
4. **代理阶段**：仅一审 / 含二审等

## 第四步：生成开案五件套

模板全文见 [`references/templates.md`](references/templates.md)（源自作者既往定稿，占位符替换即可，条款结构不要自行发挥）：

| 编号 | 文件 | 数量规则 |
|---|---|---|
| 01 | 委托代理合同 | 一份，多委托人列甲方一、甲方二 |
| 02 | 案件分析报告 | 一份 |
| 03 | 补充材料清单 | 一份 |
| 04 起 | 授权委托书（每委托人一份） | 文件名带委托人姓名 |
| 05 起 | 法定代表人身份证明（每单位委托人一份） | 文件名带单位名称 |

生成要求：

- **命名**：`01.委托代理合同.docx`、`04.授权委托书（张三）.docx`。
- **案件分析报告**：如配置了自己的文书模板或知识库，先检索同案由的既往文书，复用既有抗辩思路和论证片段；没有就按下面的结构直接写。结构：案情梳理、法律关系、争议焦点、双方攻防、风险与胜负态势（**定性表述，禁百分比**，守则 E7）、办案思路、下一步动作。需要更深的分析可调用 case-analyzer。引用法条逐条到权威法规数据库（北大法宝、元典、国家法律法规数据库等）现查原文核对，不得凭记忆或本地副本代替核对；核不了标"待核"。
- **补充材料清单**按模板骨架结合本案定制：委托手续材料、身份关系材料、合同与结算材料、付款凭证、争议协议原件、其他（对方资信、关联诉讼），并写明举证期限。
- **授权委托书**代理权限用模板中的特别授权全项列举，不要缩写成"特别授权"四个字。
- **出 docx**：有 litigation-doc-generator 一类文书母版 skill 就用它直出；没有就用 python-docx 按模板逐段生成，再调用 gongwen-format 公文排版（没有 skill 机制的工具直接读 `skills/gongwen-format/SKILL.md` 照做）。直接以最终文件名落盘，中间稿放系统临时目录。
- 律师信息（姓名、律所、地址、电话）从执业档案读，没有档案就留 `〔待补：承办律师〕`、`〔待补：律师事务所〕` 等占位，不要凭记忆写。

## 第五步：汇报与衔接

1. 列出已生成文件清单和归档位置。
2. ⚠️ 高亮：开庭时间、举证期限、答辩期，以及委托合同和身份证明中的 `〔待补〕` 项。
3. 问一句是否继续起草答辩状 / 质证意见，本 skill 不代劳（证据目录与质证可转 evidence-organizer）。

## 边界

- 不做答辩状、质证意见、代理词（诉讼文书类 skill 的事）。
- 不做深度判决书分析（judgment-analyzer 的事）。
- 收费金额、风险比例等商务条款没有用户输入时一律占位，不得虚构数字。
