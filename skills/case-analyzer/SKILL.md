# 案件分析统一入口

## 一、模式路由

| 模式 | 任务 | 详细规程 |
|---|---|---|
| `intake` | 接案初评、是否值得代理 | [mode-intake.md](references/mode-intake.md) |
| `setup` | 建案件工作区和期限表 | [mode-setup.md](references/mode-setup.md) |
| `analyze` | 法律关系、争议焦点、证据缺口 | [mode-analyze.md](references/mode-analyze.md) |
| `doc` | 起诉状、判决书、庭审笔录分析 | [mode-doc.md](references/mode-doc.md) |
| `strategy` | 诉讼目标、路径、攻防和风险 | [mode-strategy.md](references/mode-strategy.md) |
| `brief` | 开庭前、合伙人会议或客户汇报简报 | [mode-brief.md](references/mode-brief.md) |

用户表达足以判断模式时直接执行，只读取该模式的规程。确实同时命中多个模式时，先完成用户最直接要求的模式，不自动连跑；是否继续另一个模式交付后再由用户决定。

## 二、按需前置检查

- 立场会改变分析方向时确认原告、被告、上诉人、被上诉人、申请人或被申请人；从材料能判断时不再提问。
- 只有涉及期限计算、时效、当前状态或报告基准日时才读取系统日期。纯历史事实分析不单独运行取时命令。
- 已有案件工作区时读取必要字段；只有 `setup` 模式或用户明确要求建档时才创建、维护 `matter.md`、`matter.yaml` 和 `history.md`。工作区根目录默认 `~/legal-profile/matters/`，可用环境变量 `MATTERS_ROOT` 改到别处（见 [workspace-spec.md](references/workspace-spec.md)）。
- PDF 有文字层时直接读取；没有文字层且相关页面确需使用时才 OCR。
- 大材料按与争点的相关性分批读取。覆盖范围影响结论时说明范围，不默认逐节制作完整阅读台账。
- 管辖、涉外、利冲等问题只有与当前任务有关时提示，不作为每个模式的固定六项门禁。

## 三、分析原则

- 结论围绕用户当前问题，不把一个案件分析自动扩展成时间线、要件表、证据目录、检索报告和诉讼文书全套。
- 已有时间线、材料摘要、检索详情或既有分析直接复用，不重复生成。
- 法律和案例检索用你可用的权威来源（北大法宝、元典等法律数据库的 MCP 或网站，国家法律法规数据库，中国裁判文书网），普通问题采用轻量模式；引用前必须取到条文或裁判原文，检索片段只算候选。
- 风险分级和商业摩擦双轴只在用户要求风险矩阵、合同商务评估或确有多项风险需要比较时使用，不是所有案件分析的固定格式。
- 胜诉判断使用定性表达并说明取决于哪些事实和证据，不给百分比。

## 四、输出

- 默认只交付当前模式的一份结果，不自动加复核须知、决策树、清单外一问或另一个客户版。
- 用户要求内部工作底稿时，可以集中列来源、已读范围和待确认事项；普通答复不加形式化封面。
- 只有用户要求落盘时才写报告文件。只有 `setup` 或明确要求记录案件进展时才更新案件工作区和 `history.md`。
- 需要转入其他专项 skill 时，交付当前结果后简要提示，不在本轮自动调用。规程里提到的 skill 本仓库没有的（如 chronology-builder、litigation-doc-generator、brief-section-drafter、deposition-prep、case-retrieval-report），有同类工具就用，没有就由你直接按规程写明的结构完成。

## 五、停止条件

当前模式已经回答用户问题，关键前提和限制已经说明时立即停止。不要为了完整案件工作流继续运行其他模式或生成额外文件。

## 六、版本

- v2.0.0（2026-09-02）：六项固定门禁改为按需检查；取消默认取时、建档、逐节阅读台账、双轴评分、复核封面、决策树和 history 更新；每次只运行一个模式。
