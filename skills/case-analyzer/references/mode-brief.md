# mode: brief（案件简报）

> 合并自 `matter-briefing`。原 skill 声明"案件目录用户手动建立，本 skill 不创建"，
> 现在 `setup` 模式负责创建，本模式只负责读取与呈现。

## 什么时候用

重要时刻前把案件状态一次性梳清：开庭前、合伙人 call 前、客户汇报前、重大决策点。

**简报不产生新判断**，它是把已有的分析按受众重组。缺少底层分析时先跑 `analyze` 或 `strategy`。

## 前置

1. **读工作区**：`matter.yaml` + `matter.md` + `history.md`。工作区不存在时问用户：先跑 `setup` 建档，还是走临时模式（只出简报不写盘）。
2. **重算期限**：用当前系统时间重算所有 `remaining`，与存档值不符就更新 yaml（见 [time-discipline.md](time-discipline.md)）。
3. **选简报类型**：三种类型受众不同，内容取舍完全不同，**必须先确认是哪一种**。

## 三种类型

| 类型 | 受众 | 长度 | 语言 |
|---|---|---|---|
| 开庭前简报 | 出庭律师自己 | 详尽 | 全专业术语 |
| 合伙人 call 简报 | 合伙人 | 5 至 10 分钟看完 | 专业但压缩 |
| 客户汇报简报 | 客户 | 短 | 去术语，走安静模式 |

---

## 类型一：开庭前简报

庭前 1 至 3 天用。目标是律师带着它进法庭就够了。

```markdown
# [案件名称] 开庭前简报

> ⚠️ 复核须知
> - **来源**：matter.yaml + history.md + [本次新增材料]
> - **已读**：[材料结构清单]
> - **待复核**：N 处 [review]
> - **签发前**：(1) 与当事人对齐庭审策略 (2) 复核质证清单是否齐全
> - **开庭时间**：YYYY-MM-DD HH:MM ｜ 距今 N 天
> - **分析基准日**：YYYY-MM-DD

## 〇、庭前必办（🔴 项）
[未完成的硬期限、未提交的材料、未确认的授权]

## 一、案件状态
| 项 | 内容 |
|---|---|
| 案号 | |
| 当事人 | 原告 ... ｜ 被告 ... |
| 我方立场 | |
| 案由 / 阶段 | |
| 标的额 | |
| 审判人员 | [已知裁判倾向] |

## 二、争议焦点（按庭审预计顺序）
| # | 焦点 | 我方观点 | 对方观点 | 法律风险 | 商业摩擦 | 态势 |

每个焦点补一句**胜负手**：这一项最终取决于什么。

## 三、关键证据备查
| 编号 | 证明内容 | 强度 | 庭审用途 | 存放位置 |
|---|---|---|---|---|
| 证据 3 | | 🔴 单一直接 | 主张依据 | 材料/... |
| 证据 7 | | 🟡 旁证组合 | 弹劾对方 | 材料/... |

## 四、对方薄弱点与我方杀手锏
- 对方 🔴 致命缺口：[要件未证 / 证据违法 / 陈述矛盾]
- 我方杀手锏：[关键弹劾材料 / 对方已作的自认 + 笔录页码]

## 五、预判对方会打什么
[推演对方的主要主张与突袭可能，各配一句应对]

## 六、庭审策略选项
> 1. **激进推进** 全部弹劾 + 主张全部诉请
> 2. **稳健固定** 重点固定关键自认，弹劾留二审
> 3. **保留杀手锏** 重要弹劾留到对方最后陈述时反咬
> 4. **预备和解** 观察对方态度，必要时申请调解
> 5. 其他

## 七、清单之外的一问
> [典型：如果法官当庭问和解意向，我方授权范围是什么？现在确认还来得及]
```

## 类型二：合伙人 call 简报

合伙人时间有限，**结论前置，细节后置**。

```markdown
# [案件名称] 合伙人 call 简报

> ⚠️ 复核须知（简化版：来源 + 待复核 + 基准日）

## 一、一句话总结
[案号 + 当事人 + 案由 + 当前阶段 + 我方立场 + 一句现状]

## 二、当前最重要的三件事
1. **🔴 阻断**：[必须立即解决 + 我方建议]
2. **🟠 高**：[强烈建议关注 + 备选方案]
3. **🟡 中**：[应当关注，不紧急]

## 三、需要合伙人决策的事项
| # | 决策点 | 选项 | 我方推荐 | 不决的后果 | 最晚决策时点 |

**最晚决策时点必填**，它是这份简报存在的理由。

## 四、关键数字
| 项 | 值 |
|---|---|
| 标的额 | |
| 我方诉请 | |
| 已投入工时 | |
| 预计剩余周期 | |
| 胜诉预判 | [定性四档，禁百分比] |

## 五、下一个硬期限
[事项 + 算式 + 剩余天数 + 风险标记]

## 六、合伙人不必看但你可能想知道的
[第二顺位信息]
```

## 类型三：客户汇报简报

走守则 A23 安静模式：去掉全部内部叙述、去掉律师术语、不暴露内部分歧。

```markdown
# [案件名称] 情况说明

> 说明：本文为向委托人汇报的情况说明。
> [复核须知仅保留来源与签发前两项]

## 一、目前进展
[两三段日常语言陈述，不用"请求权基础""举证责任倒置"这类词]

## 二、当前的关键情况
1. ……
2. ……

## 三、下一步的选择
> 您可以选：
> 1. 走诉讼到底：预计 [周期]，费用 [区间]，可能的结果 [说明]
> 2. 争取和解：预计 [周期]，可能的条件 [说明]
> 3. 暂时观望：适用于 [条件]

## 四、我们的建议
[结合客户档案（如有）或已知的客户偏好给推荐，说明理由，不替客户决定]

## 五、需要您确认或提供的
- ……
```

**客户版禁止出现**：内部分歧、对法官的评价、对对方律师的评价、"我方杀手锏"这类内部话术、未经确认的猜测。

## 收尾动作（三种类型共有）

1. 更新 `matter.yaml` 的 `status.last_activity` 为系统时间；期限有变动的同步 `deadlines`。
2. 追加 `history.md` 一行：

```
YYYY-MM-DD HH:MM | 案件简报 | 为 [开庭前 / 合伙人 call / 客户汇报] 出具简报 | 产物/YYMMDD ...md
```

3. 客户版另存一份，文件名标明受众：`产物/YYMMDD 情况说明（客户版）.md`。

## 重要规则

1. 简报类型必先确认，三种受众取舍完全不同。
2. 期限必须用当前系统时间重算，不沿用存档值。
3. 合伙人版的"最晚决策时点"必填。
4. 客户版走安静模式，去术语去内部叙述。
5. 简报不产生新判断，缺分析先补分析。
6. 利冲提醒：新案件首次出简报时提醒一次，不阻断。
