# 时间纪律

> 本文件吸收自 SuitAgent 的 TimeRules.md，按律师业务场景改写。
> 适用于 case-analyzer 全部六个模式，无例外。

## 为什么单独立一份

律师业务里日期算错就是事故。上诉期算错 15 天，案子直接死掉，性质比引错法条更直接：引错法条对方会指出来，日期错了没人提醒。

而 AI 写日期的默认失败模式恰恰是"看起来很合理的编造"：不查系统时间就写「2026 年 7 月」，把上个月的事写成本月，把还没发生的事写成已完成。这类错误在成稿里极难被肉眼发现，因为它读起来毫无异常。

## 三条铁律

### 铁律一：所有日期取自系统时间

任何模式动笔前先取系统时间：

```bash
# bash / zsh
date "+%Y-%m-%d %H:%M:%S"
# PowerShell
Get-Date -Format "yyyy-MM-dd HH:mm:ss"
```

得到的时间是本次分析的**基准日**，写进复核须知封面。后续所有"今天""本月""剩余天数"以它为准。

禁止行为：
- 凭印象写当前日期
- 从材料里某个日期推断"现在大概是什么时候"
- 沿用上一轮对话里的日期（对话可能跨天）

### 铁律二：已完成事件不得使用未来日期

时间线必须满足单调顺序：过去 → 基准日 → 未来。

写完时间线后逐条自检：
- 标「已完成」的事件，日期是否都 ≤ 基准日？
- 标「预计」的事件，日期是否都 > 基准日？
- 相邻两个诉讼节点的间隔是否符合常识？（立案到开庭通常 1 至 3 个月，不会是 3 天）

任何一条不满足就是错的，改日期而不是改判断。

### 铁律三：法定期限必须写出算式

只写结论不写算式的一律视为未核。

```
✅ 上诉期：判决书送达日 2026-07-20 + 15 日 = 2026-08-04，距基准日剩余 9 天 🟠
❌ 上诉期：2026-08-04
❌ 上诉期还剩 9 天
```

算式让错误可被复核。写了算式，主办律师扫一眼就能发现起算日取错；只写结论，错了没人看得出来。

## 期限计算口径

### 起算日

《民事诉讼法》期间的计算，**期间开始的时和日不计算在内**，从次日起算。写算式时起算日写"送达日"，但实际计算从送达次日起。为避免歧义，算式统一写成：

```
送达日 2026-07-20（不计入）→ 起算 2026-07-21 → 15 日届满 2026-08-04
```

### 常见法定期限

| 事项 | 期限 | 起算点 |
|---|---|---|
| 一审民事答辩 | 15 日 | 收到起诉状副本次日 |
| 一审民事上诉 | 15 日 | 判决书送达次日 |
| 裁定上诉 | 10 日 | 裁定书送达次日 |
| 举证期限 | 法院指定 | 举证通知书载明 |
| 管辖权异议 | 15 日 | 提交答辩状期间内 |
| 申请再审 | 6 个月 | 判决裁定发生法律效力次日 |
| 涉外一审答辩 | 30 日 | 收到起诉状副本次日 |
| 涉外上诉 | 30 日 | 判决书送达次日 |

**上表仅作提示，不作为引用依据。** 对外文书里写具体期限时，仍须按守则 A9 联网核对现行条文，本表不替代核对。

### 节假日顺延

期间届满的最后一日是法定休假日的，以休假日后的第一日为届满日期。

实务处理：算出届满日后检查是否落在周末或法定节假日，落在则顺延并在算式里写明：

```
起算 2026-07-21 → 15 日届满 2026-08-04（周二，非假日，不顺延）
```

不确定某日是否为法定节假日时，标 `[review]` 交主办律师确认，**不要猜**。

## 期限风险预警

在 `matter.yaml` 和所有报告里，按剩余天数打标：

| 剩余 | 标记 | 含义 |
|---|---|---|
| ≤ 3 天 | 🔴 | 立即处理，其他事项让路 |
| 4 至 7 天 | 🟠 | 本周内必须完成 |
| 8 至 15 天 | 🟡 | 已进入准备窗口 |
| > 15 天 | 🟢 | 正常 |
| 已过期 | 🔴 已逾期 | 单独列出，评估补救路径 |

已逾期的期限**必须单独成段提示**，不得混在正常期限表里一笔带过。

## 时间戳格式

| 用途 | 格式 | 示例 |
|---|---|---|
| 报告基准日 | `YYYY-MM-DD` | 2026-07-26 |
| history.md 条目 | `YYYY-MM-DD HH:MM` | 2026-07-26 14:30 |
| 产物文件名前缀 | `YYMMDD ` | `260726 争议焦点分析.md` |
| yaml 日期字段 | `YYYY-MM-DD` | 2026-07-26 |
| 期限剩余 | `[X天]` | [9天] |

## 出稿前时间自检

每份产物交付前逐项过一遍：

- [ ] 已取系统时间得到基准日，并写进复核须知封面
- [ ] 所有日期不晚于基准日（预计事项除外，且已标「预计」）
- [ ] 时间线顺序单调，无倒挂
- [ ] 每个法定期限都带算式，不是光秃秃一个日期
- [ ] 剩余天数与基准日一致（不是上一轮算的旧值）
- [ ] 期限风险标记与剩余天数对应
- [ ] 已逾期项单独成段
- [ ] 不确定的节假日顺延标了 `[review]`

## 发现时间错误后的修正流程

1. 停止当前动作，不要在错误时间基础上继续写。
2. 重新取系统时间作为基准日。
3. 列出所有受影响字段：`matter.yaml` 的期限段、`matter.md` 的时间线与待办、本轮报告的封面与期限表、`history.md` 的条目。
4. 批量修正，逐项复核逻辑一致性。
5. 在 `history.md` 追加一行修正记录，写明改了什么、为什么。

不允许只改发现的那一处而不检查其余，时间错误通常成片出现。
