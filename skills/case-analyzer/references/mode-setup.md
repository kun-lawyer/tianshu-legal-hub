# setup：建立案件工作区

本模式建立当前案件入口。遵循 SKILL.md，不自动启动案件分析、证据整理或开案五件套。

## 输入与判断

- 从用户指定卷宗或已有材料确认案件身份、我方立场、当前阶段。目录名和历史台账上的"在审"标签只能作为线索。
- slug 优先沿用已有值；新建时按 [workspace-spec.md](workspace-spec.md) 的命名规则生成，不因技术名称反复打断用户。案件身份有歧义才向用户提问。

## 建立工作区

原件保留在源目录，不默认复制整卷或 OCR 全部文件。工作区保存 `matter.yaml`、`matter.md`、`history.md`，记录源目录及必要字段。

用本 skill 自带脚本建骨架（`<skill目录>` 指本 skill 所在目录）：

```bash
python "<skill目录>/scripts/init_matter.py" --slug "260726 甲某 民间借贷" --name "甲某诉乙某民间借贷纠纷案" --our-side 被告
```

- 工作区根目录默认 `~/legal-profile/matters/`，设环境变量 `MATTERS_ROOT` 可改到别处（例如放进你自己的同步盘）。
- 起算日明确时加 `--served YYYY-MM-DD` 和 `--deadlines 答辩期限,举证期限`，脚本按"送达次日起算"预填期限；起算日、期限依据不明确时不要传，`deadlines` 留空并记录待核事项。脚本预填的期限仍须对照传票、通知书原文核实后才能当真。
- 其余参数（`--case-no`、`--cause`、`--court`、`--client`、`--amount`、`--stage`）材料里有才填，没有就留空。`python init_matter.py --help` 查看全部参数。
- 如果你有自己的案件台账或知识库关联脚本，可以替换本脚本，只要产出的三份文件字段一致。

## 输出与维护

- matter.yaml 为案件工作区状态源，matter.md 为可重建阅读视图，history.md 只记录实际建档、状态变更和同步。
- 已有同源案件复用原工作区；发现重复目录时先提示修正，不新建第二份。
- 仅为核实关键事项读取材料，按请求决定是否另出清单。一般建档不附复核封面、决策树和额外报告。

未知案件要素保持空值或"待核实"。工作区建好、字段核对无误后停止。
