# mode: strategy（诉讼策略）

> 合并自 `case-strategy-analyzer` 的第 4 至 6 步（胜诉预判、策略制定、战略报告输出）。
> 前置的案情建模与争议焦点识别见 [mode-analyze](mode-analyze.md)。

## 什么时候用

争议焦点已经梳清，需要决定怎么打：目标定在哪、走哪条路径、风险怎么防、底线在哪。

**未做 analyze 就进本模式的**，先补一轮焦点识别再来。没有焦点的策略是空话。

## 输入

必需：
- 争议焦点清单（或已填好 `issues` 段的 `matter.yaml`）
- 我方立场
- 客户目标与约束（要钱还是要关系、能拖多久、预算多少）

客户目标不清楚**必须问**。同一个案子，客户要"尽快拿钱"和要"打出个说法"，策略完全相反。

## 分析深度

| 层级 | 覆盖 |
|---|---|
| 基础 | 法律规则评估、定性预判 |
| 深度（默认） | 加证据情况、举证难度、司法实践、对方抗辩推演 |
| 专家级 | 加类案检索、法官裁判倾向、地域因素、敏感性分析 |

专家级需要跑类案检索（转 `case-retrieval-report` 或 `yuandian-law-search`），检索结果走守则 A6 自检后才能用。

## 工作步骤

### 1. 胜诉预判

**定性四档，禁百分比**（见 SKILL.md「胜诉预判口径」）。每档后面必须跟支撑理由：

| 档 | 含义 |
|---|---|
| 较有把握 | 核心焦点我方占优，证据闭合，对方抗辩明显站不住 |
| 中等 | 有胜有负，结果取决于某个可争取的关键点 |
| 把握不大 | 核心焦点我方不利，需要靠程序或次要争点找机会 |
| 重大不确定 | 关键事实无法查清，或法律适用本身存在分歧 |

预判必须写清**它取决于什么**：

```
✅ 中等。成败取决于 2024 年 3 月转账能否被认定为借款而非投资款。
   目前借条与微信记录支持借款，但对方持有的股东会记录若属实会构成反证。
   建议先申请调取该记录，再定最终打法。
❌ 中等，本案有一定难度。
```

### 2. 敏感性分析

列出**改变结论的变量**，标明每个变量的走向如何影响预判：

| 变量 | 若成立 | 若不成立 | 现在能做什么 |
|---|---|---|---|
| 银行流水能否调取 | 较有把握 | 把握不大 | 立即申请调查令 |
| 对方股东会记录真实性 | 把握不大 | 较有把握 | 申请鉴定或要求出示原件 |

这张表比预判结论本身更有用：它告诉律师精力该往哪里投。

### 3. 目标设定

三层，缺一不可：

- **主要目标**：全部诉请获支持的理想结果
- **次要目标**：可接受的和解或部分胜诉方案
- **底线**：低于此宁可判决不和解

底线要写成可判断的具体条件（金额、时限、履行担保），不写成"差不多就行"。

### 4. 路径比选

| 路径 | 预期结果 | 周期 | 成本 | 风险 | 适用条件 |
|---|---|---|---|---|---|
| 硬打到判决 | | | | | |
| 打到一半调解 | | | | | |
| 诉前和解 | | | | | |
| 施压后撤诉 | | | | | |

**执行可行性必须进比选。** 判决拿到手执行不下来，等于选了最贵的一条路走到最坏的结果。对方财产状况未查的，把"查财产"列为路径比选的前置动作。

### 5. 策略要点

分四块展开：

- **证据策略**：先出什么、留什么、哪些等对方出招后再出
- **法律主张策略**：主位与备位请求怎么摆，备位请求会不会削弱主位的说服力
- **程序策略**：管辖异议、财产保全、追加当事人、鉴定申请、调查令，各自的时点与代价
- **庭审策略**：争点顺序、质证重点、预留的弹劾材料

程序动作要标时点，很多程序权利有失权效（如管辖异议须在答辩期内提出）。

### 6. 风险防控

每项风险打双轴（守则 A22），并写应对预案：

| 风险 | 法律风险 | 商业摩擦 | 触发条件 | 预案 |
|---|---|---|---|---|
| 对方反诉 | 🟠 | 🔴 | 我方主张违约金过高 | 预备反诉答辩要点，评估合并审理影响 |
| 财产被转移 | 🔴 | 🟡 | 立案后至保全前 | 立案同时申请保全 |

任一轴为 🔴 的整项计 🔴，在报告中前置。

### 7. 回填数据层

更新 `matter.yaml` 的 `strategy` 段：`outlook`（定性）、`outlook_reason`、`primary_goal`、`fallback`、`bottom_line`。同步 `matter.md`，追加 `history.md`。

文件名：`产物/YYMMDD 诉讼策略.md`

```markdown

## 一、胜诉预判
**[定性档次]**。[取决于什么 + 理由]

## 二、敏感性分析
| 变量 | 若成立 | 若不成立 | 现在能做什么 |

## 三、目标
- 主要：
- 次要：
- 底线：[具体可判断的条件]

## 四、路径比选
| 路径 | 预期 | 周期 | 成本 | 风险 | 执行可行性 |

**推荐路径**：[哪条 + 为什么]

### 5.2 法律主张策略
### 5.3 程序策略（含时点与失权风险）
### 5.4 庭审策略

## 六、风险防控
| 风险 | 法律风险 | 商业摩擦 | 触发条件 | 预案 |

| 动作 | 计划时点 | 硬期限 | 剩余 |
[硬期限带算式]

> 1. **按推荐路径推进** 我起草下一份文书（有诉讼文书 skill 就用它；没有我按法定格式写正文，用 python-docx 出 docx 后调用 gongwen-format 排版）
> 2. **先做程序动作** 我起草保全申请 / 管辖异议 / 调查令申请
> 3. **补强证据后再定** 我列取证清单（转 evidence-organizer）
> 4. **走和解** 我起草谈判要点与让步梯度
> 5. **要更深的论证** 我跑类案检索（转 case-retrieval-report）
```

## 重要规则

1. 胜诉预判定性表达，禁百分比，档次后必须给取决于什么。
2. 敏感性分析必做，它决定精力投向。
3. 底线写成可判断的具体条件。
4. 执行可行性进路径比选，不查财产不谈胜负。
5. 程序动作标时点，注意失权效。
6. 风险双轴打满，🔴 项前置。
7. 不替律师做决定，决策树给选项。
