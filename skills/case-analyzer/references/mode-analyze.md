# mode: analyze（案情建模与争议焦点）

> 合并自 `case-strategy-analyzer` 的第 1 至 3 步（案情建模、法律关系图谱、争议焦点识别）。
> 该 skill 的第 4 至 6 步（胜诉预判、策略制定、战略报告）归入 [mode-strategy](mode-strategy.md)。

## 什么时候用

案件事实基本清楚，需要把它拆成可攻防的结构：谁对谁主张什么、争的到底是哪几件事、证据缺在哪。

这是 `strategy` 的前置。没有争议焦点就谈策略，谈的是空气。

## 输入

必需：
- 案件事实（或已建好的 `matter.yaml`）
- 我方立场
- 案件类型（民事 / 劳动 / 合同 / 行政 / 刑事 / 知产 / 公司）

有则更好：对方的起诉状或答辩状、证据清单、既往沟通记录。

## 工作步骤

### 1. 案情建模

从材料中抽取**要件事实**，区分三类：

| 类别 | 含义 | 处理 |
|---|---|---|
| 已证事实 | 有证据支撑且对方不争 | 作为分析基础 |
| 争议事实 | 双方各执一词 | 进争议焦点 |
| 待证事实 | 我方主张但暂无证据 | 进证据缺口 |

事实条目一律标出处。当事人单方陈述标为「当事人陈述，待印证」（守则 A10）。

需要完整时间线时跑 `chronology-builder`，本模式不重复实现。

### 2. 法律关系图谱

用文字或 mermaid 描述当事人之间的法律关系网络，标出冲突点：

```mermaid
graph LR
    A[甲某 出借人] -->|借款合同| B[乙某 借款人]
    C[案外人 丙某] -.->|以房抵债协议| B
    A -->|申请撤销| C
```

多方案件、有案外人介入、存在关联案件时，图谱是必须的。两方简单案件可以只用文字。

**关联案件要单独列**：本案的判断是否依赖另案结果？另案的既判力范围覆盖本案哪些事实？这一项漏掉会导致整个分析建在流沙上。

### 3. 争议焦点识别

用户已提出焦点的，先评估其合理性再补充遗漏；用户未提的，系统识别后按重要性排序。

每个焦点必须写全五项：

| 项 | 要求 |
|---|---|
| 焦点表述 | 写成可判断真伪的命题，不写成话题 |
| 我方观点 | 我方主张什么，凭什么 |
| 对方观点 | 对方会怎么说（没听到也要推演） |
| 双轴严重度 | 法律风险 🔴🟠🟡🟢 + 商业摩擦 🔴🟠🟡🟢 |
| 当前态势 | 我方有利 / 我方不利 / 未决 |

焦点表述示范：

```
✅ 2024 年 3 月的 50 万元转账是借款还是投资款
✅ 以房抵债协议是否构成对债权人的恶意串通
❌ 关于款项性质的问题        （话题不是命题，无法判真伪）
❌ 合同效力争议              （太宽，落不到具体事实）
```

**对方观点必须写。** 只写我方观点的争议焦点表是自说自话，等于没做。听不到对方声音时按对方立场推演，标明「推演」。

### 4. 请求权基础与要件匹配

每个焦点对应到具体法条要件，逐个要件核对我方有无对应证据。

请求权基础按以下顺序排查，前一类成立不妨碍后一类竞合，列出全部可成立的再择优：合同（履行、违约、解除后返还）→ 类合同（缔约过失、无权代理、无效或撤销后返还）→ 无因管理 → 物权请求权 → 侵权 → 不当得利。特别法有规定的（公司、劳动、票据、保险）先看特别法。

要件对照做深了走 `claim-chart`（一行一要件的完整对照表）。本模式只做到"哪个要件明显缺证据"这一层，不重复实现。

法条引用走守则 A6 自检（引的要旨真的支持这个命题吗）和 A7 原文纪律（带引号必有原文在手）。未取到原文的不替条文做描述（守则 A11）。

### 5. 证据缺口

| 待证事实 | 现有 | 缺什么 | 严重度 | 取证路径 | 可行性 |
|---|---|---|---|---|---|

🔴 级缺口指"缺了这项该焦点必输"的证据。它们要在报告最前面单独列一次。

证据目录、质证意见走 `evidence-organizer`，本模式只识别缺口。

### 6. 回填数据层

分析完成后更新 `matter.yaml`：
- `issues` 段：每个焦点一条，含双轴与态势
- `legal_relations` 段
- `evidence_gaps` 段
- `status.last_activity` 更新为系统时间

同步更新 `matter.md` 的对应章节，追加 `history.md` 一行。

## 输出格式

文件名：`产物/YYMMDD 争议焦点分析.md`

```markdown
# [案件名称] 争议焦点分析

> ⚠️ 复核须知（含分析基准日）

## 〇、致命缺口提示
[🔴 级证据缺口单独列；无则写"经核，暂无致命缺口"]

## 一、事实梳理
### 1.1 已证事实
### 1.2 争议事实
### 1.3 待证事实

## 二、法律关系图谱
[图 + 关键关系说明 + 关联案件]

## 三、争议焦点（按重要性排序）

### 焦点一：[命题式表述]
- **我方观点**：
- **对方观点**：
- **请求权基础 / 抗辩基础**：
- **双轴严重度**：法律风险 🔴 ｜ 商业摩擦 🟡
- **当前态势**：
- **胜负手**：[这个焦点最终取决于什么]

### 焦点二：...

## 四、要件匹配与证据缺口

| 待证事实 | 现有证据 | 缺口 | 严重度 | 取证路径 |
|---|---|---|---|---|

## 五、决策树
> **焦点已梳清，接下来：**
> 1. **定打法** 我跑 strategy，出目标、路径和风险防控。
> 2. **做要件对照表** 转 claim-chart，一行一要件核到底。
> 3. **理时间线** 有时间线类 skill 就转它，没有我直接按"日期 | 事件 | 出处 | 我方解读 | 对方解读"出双视角时间线。
> 4. **补证据** 我列取证清单和调查令申请要点。
> 5. **直接起草文书** 有诉讼文书 skill（如 litigation-doc-generator）就转它；没有我按法定格式写正文，用 python-docx 出 docx 后调用 gongwen-format 排版。
> 6. 其他

## 六、清单之外的一问
> [典型：对方会不会反诉？我方有没有可能被追加当事人？]
```

## 案件类型适配

| 类型 | 分析重点 |
|---|---|
| 民事 | 法律关系认定、权利义务边界、举证责任分配、损害赔偿范围 |
| 合同 | 合同成立与效力、履行抗辩、违约认定、损失范围与可预见性 |
| 劳动 | 劳动关系确认、规章制度效力、解除合法性、经济补偿计算 |
| 行政 | 职权依据、事实证据、程序正当、法律适用、裁量幅度 |
| 刑事 | 犯罪构成要件、证据合法性与证明标准、量刑情节 |
| 知产 | 权利基础、侵权比对、抗辩事由、赔偿计算方式 |
| 公司 | 股东资格、决议效力、出资责任、人格否认 |
