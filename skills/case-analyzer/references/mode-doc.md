# mode: doc（文书分析）

> 合并自 `litigation-analysis`（起诉状 / 判决书 / 庭审笔录三场景）。
> 判决书的深度要旨提取仍可转 `judgment-analyzer`，本模式做到"要旨 + 决策分流"这一层。

## 三个子场景

进入本模式先判断文书类型，走对应子流程。类型判不准就问。

| 子场景 | 输入 | 核心产出 |
|---|---|---|
| **起诉状 / 答辩状分析** | 对方提交的诉讼文书 | 对方主张拆解 + 我方应对要点 |
| **判决书 / 裁定书分析** | 一审或二审裁判文书 | 要旨提取 + 上诉或再审分流 |
| **庭审笔录分析** | 庭审、询问、调查笔录 | 关键陈述 + 矛盾点 + 后续动作 |

## 通用纪律

### 引用纪律（守则 A6、A7）

**带引号必须有原文在手。** 引用文书内容一律标页码或段落位置：

```
✅ 判决书第 8 页："双方虽未签订书面借款合同，但结合转账凭证与微信聊天记录，
   足以认定借贷合意成立"
❌ 判决书认为借贷合意成立
```

第二种写法丢掉了法院的论证路径（"结合转账凭证与微信聊天记录"），而上诉能不能翻，恰恰取决于这条论证链哪一环最脆。

### 要旨与论理三分（判决书专用）

判决书内容必须分成三层，混在一起会导致把法院的顺口一句当成裁判规则：

| 层 | 含义 | 可援引性 |
|---|---|---|
| **裁判要旨** | 直接支撑判项的核心认定 | 可作类案参考 |
| **论理** | 支撑要旨的推理过程 | 攻击点在这里 |
| **附带说理** | 与判项无必然联系的评述 | 不可当规则用 |

### 双视角风险评估

判决书分析按**上诉 / 被上诉**两种视角各打一份。即便我方赢了一审，也要写清对方可能从哪里翻，因为对方大概率会上诉。

## 子场景一：起诉状 / 答辩状分析

### 步骤

1. **拆解对方主张**：诉讼请求逐项列，每项对应其事实基础和法律依据
2. **识别请求权基础**：对方走的是哪条路径，要件齐不齐
3. **找漏洞**：要件缺失、事实与证据不匹配、法律适用错误、诉请之间自相矛盾
4. **推演对方的下一步**：起诉状里没写但庭上会补的主张
5. **形成应对要点**：逐项对应答辩思路

### 输出骨架

```markdown
## 一、对方诉讼请求拆解
| # | 诉请 | 事实基础 | 法律依据 | 要件是否齐备 | 我方应对方向 |

## 二、对方请求权基础评估
## 三、发现的漏洞（按可攻击性排序）
| # | 漏洞 | 类型 | 攻击价值 | 风险 |

## 四、对方可能的补充主张（推演）
## 五、我方应对要点
```

## 子场景二：判决书 / 裁定书分析

### 步骤

1. **基本信息**：案号、审级、合议庭、裁判日期、送达日期
2. **判项逐条列**，标明支持 / 驳回 / 部分支持
3. **要旨 / 论理 / 附带说理三分**
4. **认定的事实与我方主张的差距**：法院采信了什么、没采信什么、为什么
5. **证据采信情况**：我方哪份证据被否、否的理由是什么
6. **法律适用检查**：条文引用是否准确，有无遗漏应适用的规范
7. **双视角风险评估**
8. **上诉 / 再审分流**

### 上诉与再审分流

```
上诉（15 日 / 裁定 10 日）：
  事实认定错误、证据采信不当、法律适用错误、程序违法
  → 二审是全面审查，攻击面宽

再审（6 个月）：
  必须落入法定再审事由，门槛远高于上诉
  → 事由不落在法条列举内的，写清"不构成再审事由"，不要给虚假希望
```

**期限必须带算式**（见 [time-discipline.md](time-discipline.md)），并写入 `matter.yaml` 的 `judgment.appeal_window_due`。

### 输出骨架

```markdown
## 一、基本信息与期限
| 项 | 内容 |
| 送达日 | YYYY-MM-DD |
| 上诉期算式 | 送达日（不计入）→ 起算 X → 15 日届满 Y，剩余 N 天 🟠 |

## 二、判项
## 三、裁判要旨（可援引）
## 四、论理链条（攻击点）
| 环节 | 法院论证 | 原文页码 | 脆弱度 | 可攻击理由 |

## 五、附带说理（不可当规则用）
## 六、事实认定与我方主张的差距
## 七、证据采信情况
## 八、法律适用检查
## 九、双视角风险评估
### 9.1 我方上诉视角
### 9.2 对方上诉视角（即便我方胜诉也要写）

## 十、上诉 / 再审分流结论
[定性表达，禁百分比，结论后必须给理由]
```

## 子场景三：庭审笔录分析

### 步骤

1. **提取关键陈述**：己方、对方、证人、法官各自说了什么要紧的
2. **标记自认**：对方承认了什么对我方有利的事实，这是笔录里最值钱的东西
3. **找矛盾**：对方庭上陈述与其书面材料、与证据、与前后陈述的冲突
4. **法官关注点**：法官反复追问的地方就是他认为的争点，比任何推测都准
5. **未尽事项**：庭上没说清、需要庭后补充的

### 陈述引用纪律

关键陈述**必须逐字引用并标页码**，不得转述：

```
✅ 笔录第 14 页，被告陈述："钱是收到了，但那是他还我以前的欠款"
   → 构成收款事实的自认，同时提出新抗辩，抗辩的举证责任在对方
❌ 被告承认收到了钱但说是还款
```

转述会丢掉原话的语气和限定词，而自认的效力恰恰取决于原话的精确表述。

### 输出骨架

```markdown
## 一、庭审基本情况
## 二、对方自认（最优先）
| # | 自认内容（逐字） | 页码 | 对我方价值 | 后续用法 |

## 三、关键陈述汇总
## 四、矛盾点
| # | 陈述 A（页码） | 陈述 B / 证据 | 矛盾性质 | 弹劾价值 |

## 五、法官关注点
## 六、未尽事项与庭后动作
```

## 通用结尾（三个子场景共有）

```markdown
## 决策树
> **接下来怎么走？**
> 1. **起草上诉状 / 答辩状** 有诉讼文书 skill（如 litigation-doc-generator）就转它；没有我按法定格式写正文，用 python-docx 出 docx 后调用 gongwen-format 排版
> 2. **深挖判决要旨** 转 judgment-analyzer
> 3. **调整策略** 我跑 strategy 重估打法
> 4. **补强证据** 我列取证清单
> 5. **准备下次庭审** 转 deposition-prep 出询问提纲
> 6. 其他

## 清单之外的一问
> [典型：这份判决对我方其他在办案件有没有参照影响？]
```

## 回填数据层

- 判决书分析后填 `matter.yaml` 的 `judgment` 段与 `deadlines`（上诉期）
- 笔录分析后把新发现的争议焦点补进 `issues` 段
- `status.current` 与 `status.next_action` 更新
- 追加 `history.md`
