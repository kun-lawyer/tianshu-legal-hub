# 裁判文书分析

系统分析判决书、裁定书、裁决书等裁判文书，提取裁判要旨、法律适用逻辑、证据采信规则，为案件策略提供参考。

## 出稿前置检查（守则）

1. **side framing 必确认**：本案当事人是上诉方 / 被上诉方 / 申请再审方 / 被申请方？默认上诉方是最常见的翻车设。不知道就**停下向用户提问**。
2. **大输入协议（A16）**：判决书通常 30 至 100 页，明示读了哪部分、跳了哪些，写到复核须知"已读"行。
3. **审级识别**：一审 / 二审 / 再审，决定后续路径选项（守则 E4 二审/再审分流）。
4. **管辖识别（A21）**：涉港澳台 / 涉外 / 民族区域 → 明示框架不适用。

## 引用纪律（守则强化版）

### 要旨 / 论理 / 附带说理三分（守则 E4）

判决书"本院认为"段往往含三部分，**引用时必须明示**：

| 类型 | 含义 | 类案引用价值 |
|---|---|---|
| **裁判要旨** | 法院对争议焦点的核心判断 | 高，可作先例参考 |
| **裁判论理** | 推理过程中的具体说明 | 中，限于该案事实 |
| **附带说理** | 对当事人主张的回应、对未采纳证据的说明 | 低，**不应作裁判规则引用** |

### "对得上吗"自检（A6）

引用任何要旨前先确认：
1. 这是法院持论 vs 法院驳回的对方论点？
2. 支持你想说的命题吗？
3. 是否与相近但不同的另一条法律 / 司法解释混淆？

不过关 → 改用转述 + `[待核对原文]`，或调原文核对，或剔除。

### 带引号必有原文（A7）

加引号必须能在判决书逐字定位，否则改转述 + `[待核对：判决书第 X 页第 Y 段]`。

### 来源标签

引用法条 / 案例必标实际查询的来源，例如：`[元典]` / `[北大法宝]` / `[国家法律法规数据库]` / `[模型知识，请核实]` / `[稳定，YYYY-MM-DD 核验]`。

## 工作流程

### 1. 导入裁判文书

文字、.docx、.pdf。没有文字层的 pdf 或扫描件先调用 mineru-ocr 转 markdown（没有 skill 机制的工具直接读 `skills/mineru-ocr/SKILL.md` 照做）。

### 2. 复核须知封面

```
> ⚠️ 复核须知
> - **来源**：[元典 ✓ / 国家法律法规数据库 ✓ / 训练知识，请核实部分]
> - **已读**：判决书全文 N 页（页码：X 至 Y）
> - **待复核**：N 处标 `[review]` 需要主办律师拍板
> - **时效性**：核对引用法条现行有效性；类案最近相似案例 X 件 `[元典 已核 YYYY-MM-DD]`
> - **签发前**：(1) 与客户沟通上诉/再审意愿；(2) 复核胜诉概率定性表述
> - **视角**：本次按 [上诉方 / 被上诉方 / 申请再审方] 视角
```

### 3. 结构化分析报告

```markdown
# 裁判文书分析报告

## 一、基本信息
| 项目 | 内容 |
|---|---|
| 案号 | （2026）X01民终1号 |
| 审理法院 | XXX |
| 裁判日期 | YYYY-MM-DD |
| 案由 | XXX |
| 审理程序 | 一审 / 二审 / 再审 / 仲裁 |
| 裁判结果 | 支持 / 部分支持 / 驳回 |

## 二、当事人及诉请
（原告/申请人核心主张；被告/被申请人核心抗辩）

## 三、查明事实
（法院认定的事实，**明示与当事人主张事实的差异**）

## 四、争议焦点
| 焦点 | 原告观点 | 被告观点 | 法院认定 |
|---|---|---|---|

## 五、裁判要旨（分类标注）

### 焦点一：[争议焦点]
- **裁判要旨**：[一句话核心判断]（要旨类型：要旨 / 论理 / 附带说理）
- **裁判理由**：[法院论理]
- **法律依据**：[条文]`[国家法律法规数据库]`
- **证据采信**：[采信哪些不采信哪些 + 理由]

## 六、裁判结果
| 序号 | 诉请 | 请求金额 | 裁判金额 | 支持比例 | 理由摘要 |
|---|---|---|---|---|---|

## 七、评价与策略

### 裁判亮点
- [值得借鉴的裁判观点]

### 裁判疑点
- [可能存在的问题 / 上诉再审事由]
  - 法律适用错误？`[review]`
  - 事实认定不充分？`[review]`
  - 程序违法？`[review]`

### 二审 / 再审决策（按 side framing）

**上诉方**：
- 可主张事由：[列出每项 + 法律依据 + 支持力度]
- 胜诉可能：**定性表述**（守则 E7 禁百分比）
  - 例：较有把握 / 中等把握 / 把握不大 / 存在重大不确定

**被上诉方**：
- 对方上诉理由薄弱点：[列出]
- 维持原判可能：**定性表述**

## 八、决策树（守则 A4）

> **接下来怎么走？请选一个：**
> 1. **起草上诉状 / 再审申请书**：我按本次分析的争议焦点和论证方向起草初稿。
> 2. **上报合伙人**：我起草决策简报：核心争议、胜诉可能定性、成本/收益预估。
> 3. **找客户沟通**：我起草客户咨询纪要，明确上诉/再审意愿和成本承受度。
> 4. **接受判决**：我整理一份"为何不上诉"的内部备忘，记录决策理由。
> 5. **其他**：你想怎么处理。

## 九、清单之外的一问（守则 A5）

> **清单没问到、但有经验的律师会想到的一件事：** [例：执行风险盘点过吗？赢了二审但对方资产已被掏空，执行不下来等于没赢]
```

起草上诉状、再审申请书时：有 litigation-doc-generator 一类诉讼文书 skill 就用它；没有就按法定格式（标题、当事人信息、上诉或再审请求、事实与理由、此致、落款）写正文，用 python-docx 出 docx，再调用 gongwen-format 排版。

## 分析维度

- **法律适用**：是否准确、是否有适用错误（上诉/撤裁事由）
- **事实认定**：举证责任分配、证据采信标准、事实是否有充分证据支持
- **裁判逻辑**：三段论推理是否完整、说理是否充分、是否有矛盾或遗漏
- **程序合法性**：送达、管辖、回避等程序问题

## 重要规则

1. **side framing 必先确认**：上诉 vs 被上诉视角分析方向不同
2. **要旨 / 论理 / 附带说理三分**：引用时明示类型
3. **"对得上吗"自检**：所有判决要旨引用强制
4. **带引号必有原文**：没有就转述 + `[待核对原文]`
5. **胜诉概率定性**：禁百分比（守则 E7）
6. **复核须知封面**：必备开头
7. **大文件明示已读多少**
8. **决策树收尾 + 一问**

## 验证日志（守则 A26）

引用法条、司法解释、指导案例记录到 `verification-log.md`。近期已核过用 `[稳定，YYYY-MM-DD 核验]`。
