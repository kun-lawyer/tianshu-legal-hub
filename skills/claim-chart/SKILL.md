# 法律要件对照表

诉讼律师最重要的工作之一：**把每个法律要件对应到具体证据**。

## 用途

- 起诉状起草前：确认我方主张的每个要件都有证据支持，没有就先补
- 举证质证前：清楚哪些要件证据强、哪些薄弱
- 答辩起草：找对方主张要件中**未证或证据不足**的薄弱点
- 上诉再审前：检查原审中哪些要件未被认定，要件证据链断在哪里

## 出稿前置检查（守则）

1. **侧重必确认**：我方是主张方还是反驳方？主张方要把每个要件填满；反驳方要找对方要件的薄弱点
2. **法律基础必明示**：依据哪一条法律（民法典、合同法、侵权责任法等）？守则 A6 "对得上吗"自检：要件就是法条中的"构成条件"
3. **证据来源标签**：每条证据打 `[当事人提供]` / `[公证保全]` / `[法院调取]` / `[第三方平台]`
4. **大输入协议**：证据多时（>20 份）声明覆盖范围

## 标准格式

### 复核须知封面（守则 A1）

```
> ⚠️ 复核须知
> - **来源**：[国家法律法规数据库 ✓ 法条 / 当事人提供 ✓ 证据]
> - **已读**：N 份证据材料 + 起诉状/答辩状 + 既往判决（如有）
> - **待复核**：N 个要件标 🔴 缺证据；M 个要件标 🟡 证据强度不够
> - **时效性**：法条引用现行有效 `[已核 YYYY-MM-DD]`
> - **签发前**：(1) 与当事人确认 🔴 要件是否还有补证空间；(2) 决定是先补证还是先起诉
> - **侧重**：本次按 [主张方 / 反驳方] 视角
```

### 要件对照表

```markdown
# [案由] 法律要件对照表

**依据**：《民法典》第 N 条 / 司法解释 / ……  
**侧重**：主张方 / 反驳方  
**当事人**：[原告 / 被告 / ……]

| 要件 | 法条原文 | 我方证据 | 来源 | 证据强度 | 证据满足度 | 备注 |
|---|---|---|---|---|---|---|
| 要件一：[A] | "..." (民法典 X 条) `[国家法律法规数据库]` | 证据 1：[XX] | [当事人提供] | 🔴 单一直接 | 🟢 充分 | |
| 要件二：[B] | "..." (民法典 X 条) `[国家法律法规数据库]` | 证据 5 + 7 | [公证保全] | 🟡 旁证组合 | 🟡 部分支持 | 建议补 [Y] 证据 |
| 要件三：[C] | "..." | **无** | 无 | 无 | 🔴 **缺证据** | 必补：[具体取证方向] |
| 要件四：[D] | "..." | 证据 12 | [训练知识，请核实] | 🟢 背景 | 🟠 弱 | 该证据本身待核 |
```

### 证据强度标签（与 evidence-organizer 一致）

| 等级 | 含义 |
|---|---|
| 🔴 **单一直接** | 单凭这一份就能证明该要件 |
| 🟡 **旁证组合** | 单份不够，需配合其他证据 |
| 🟢 **背景** | 仅作背景或补强 |

### 证据满足度

| 等级 | 含义 |
|---|---|
| 🟢 充分 | 要件满足、举证责任已尽 |
| 🟡 部分支持 | 有证据但弱，对方质证可能撼动 |
| 🟠 弱 | 证据存在重大瑕疵或单凭无法证明要件 |
| 🔴 缺证据 | 该要件**没有任何证据**，必补 |

## 反驳方版（被告 / 被申请方视角）

对方主张方需证明全部要件。**对方任一要件 🔴 或 🟠，就是我方答辩突破口**。

要件之外，按三类排查我方抗辩，每类问一次"有没有"：权利障碍（合同未成立、无效、主体不适格）、权利阻止（同时履行或先履行抗辩、诉讼时效、质量异议）、权利消灭（已清偿、抵销、解除）。三类的举证责任都在我方，列出后同样要对应证据。

| 对方主张的要件 | 对方证据 | 我方质证要点 | 我方反驳证据 | 突破力度 |
|---|---|---|---|---|
| 要件一：[A] | 证据 a | 真实性认可，关联性弱 | 无 | 🟡 部分突破 |
| 要件二：[B] | 证据 b | 合法性存疑（取证违法） | 证据 5 反驳 | 🔴 重大突破 |
| 要件三：[C] | **无** | 无 | 无 | 🔴 **致命缺口** |

## 决策树（守则 A4）

```
> **接下来怎么走？请选一个：**
> 1. **🔴 要件优先补证**：我列出每个 🔴 要件的可能取证方向 + 难度评估。
> 2. **修改诉讼请求**：删除无法证明的请求，集中证据到能赢的要件。
> 3. **起草起诉状**：现状已可起诉，起草起诉状。
> 4. **起草答辩状反驳**：反驳方视角，针对对方 🔴 致命缺口起草答辩。
> 5. **其他**
```

起草起诉状、答辩状时：有 litigation-doc-generator 一类诉讼文书 skill 就用它；没有就按法定格式（标题、当事人信息、诉讼请求或答辩意见、事实与理由、此致、落款）写正文，用 python-docx 出 docx，再调用 gongwen-format 排版（没有 skill 机制的工具直接读 `skills/gongwen-format/SKILL.md` 照做）。

## 清单之外的一问（守则 A5）

```
> **清单没问到、但有经验的律师会想到的一件事：** [例：法律要件齐全了，但当事人事先在某邮件中"自认"过对己方不利的事实，这个自认可能在庭审中被对方拿出来反咬，需要先想好怎么应对]
```

## 应用场景示例

### 合同违约之诉（民法典 577 条）

要件清单：
1. 合同关系成立（要件一）
2. 对方违反约定（要件二）
3. 给我方造成损失（要件三）
4. 违约与损失有因果关系（要件四）

### 侵权之诉（民法典 1165 条）

要件清单：
1. 侵权行为存在
2. 损害结果发生
3. 行为与损害有因果关系
4. 行为人有过错（过错责任）

### 不当得利之诉（民法典 122 条）

要件清单：
1. 一方获益
2. 另一方受损
3. 二者间有因果关系
4. 无合法根据

每个案由按对应法条逐一列要件，然后对每个要件检查证据匹配度。

## 重要规则

1. **法条做"对得上吗"自检**：确认要件是法条中真正的构成条件
2. **证据来源标签必标**
3. **🔴 要件不打补丁就不许起诉**，除非客户明示接受风险
4. **反驳方版独立**：找对方致命缺口
5. **复核须知封面 + 决策树 + 一问**
