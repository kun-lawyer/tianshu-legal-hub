# 面板出稿手册

资料文件里 `events[].detail` 是 JSON，本人在面板的待办或近两周安排上点了「出稿」：
- `from`：`待办` 或 `日程`；`title` 事项；`case_name` 关联案件；`detail` 待办全文（来源、要点、材料路径）；`task_id`、`sub_no` 待办编号和分支序号
- 日程另有 `date`、`time`、`kind`（开庭、举证期限、上诉期限、会议等）、`location`、`case_id`
- `want`：本人写的"要出什么"，可能为空；`folder`：本人指定的存放目录，可能为空

`answers` 非空时是本人对你上一轮提问的回答，接着办。

`by` 为"定时"的是期限派单（举证期限、上诉期限前三天自动派的）：先查重，卷宗里已有本次期限对应的证据目录、上诉状或上诉评估意见（初稿、定稿均算）的，第一行写"没事可做：已有《<文件名>》"结束；案件标了调解中的，上诉、举证材料照出，回执里提一句调解状态。

目标：在对应的电脑文件夹里出一份本人能直接改的稿。**稿只放文件夹，不发飞书**（本人 2026-11-16 定）。拿不准的先问，不先出一版碰运气。

## 一、定出什么

1. `want` 写了的，照它出。`want` 用"；"隔开列了几份文书的（本人在面板勾选的），逐份出，每份一个文件，几份之间的事实、数字、口径保持一致；其中写的不是文书名而是要求的（如"发言 10 分钟"），作为对各份稿子的要求。
2. 没写的，从事项判断：

| 事项 | 出什么 | 怎么出 |
|---|---|---|
| 起草、修改某文书（答辩状、代理词、质证意见、上诉状、律师函、法律意见书、合同、制度……） | 该文书 | 诉讼文书有 litigation-doc-generator 的母版直出，法律意见书有 law-opinion-writer 的用它；没有时按 `AGENTS.md`「skill 怎么找」的替代做法；"修改"的先抽回本人现稿正文（`dump_docx` 或 `pandoc -t plain`）在上面改 |
| 审阅、审查材料或合同 | 审阅意见或批注版 | 顾问单位合同有 guwen-review 的用它，没有时 contract-review 出批注版、评审表套自备模板；其他走 contract-review；材料审阅出《关于××的审阅意见》 |
| 回复、答复某人（客户提问、对方函件） | 答复稿 | 微信答复写 `.md`，正式回函按律师函或函件格式出 docx（有母版用母版，没有用 gongwen-format 排版） |
| 准备发言、讲座、会议 | 发言提纲或会议材料 | `.docx`，gongwen-format 排版 |
| 日程：开庭 | 本人点的是出稿而不是「出作战包」，要的多半是单份文书 | `want` 为空就问要哪份（代理词庭审发言版、质证意见、证据目录、发问清单） |
| 日程：举证期限 | 证据目录及举证材料清单 | evidence-organizer 或证据目录母版 |
| 日程：上诉期限 | 上诉评估意见，或上诉状 | `want` 为空就问要哪个 |

3. **以下情形交 `ask`，一次问清，不出稿**：判断不出要出什么；同一事项可能是两种文书；立场（代表哪方、让不让步）材料里看不出；对象、篇幅、提交方式会实质改变稿子。1 至 3 个问题合成一张卡，每题 2 至 3 个具体选项，推荐项放首位标"（推荐）"，正文先一句说清这件事和你的判断。事项本身不是出稿的事（问人、跑法院、选人）的，也问："这件事要出什么稿"，选项给最可能的两种加"不用出稿"。

## 二、定放在哪

1. `folder` 指定了的，放那里。
2. 否则依次找：待办描述里的「卷宗：<路径>」行；`日志\待办材料.json` 里该待办或该案子简称绑定的 `folder`；`python 脚本\找案件目录.py <案号或当事人>`；`python 脚本\ledger.py find <当事人>`。
3. 卷宗里按现有结构放：有审级目录的进对应审级（判断方法见 `手册\开庭作战包.md` 第三节）；有「我方文书」「4.我方文书」这类目录的放进去；顾问单位非诉事项按 `手册\送审收件.md`「归档目录看交付物」一段。不新建一级目录。
4. 对不上卷宗的（律协、所务、讲座），找资料根目录下名字相近的事务目录；仍找不到，交 `ask` 给 2 至 3 个候选目录，外加"放仓库的 `助理产出\`"。

## 三、读材料与出稿

1. 先读 `detail` 里写了路径的材料，再读卷宗里最新的法院文书、对方材料和我方已出文书；扫描件走 mineru-ocr。
2. 正式起草或实质修改前，如有自己的知识库，先检索一次同类文书和论证片段。
3. 文件名 `<文书名>（初稿）.docx`（答复稿 `.md`）；目标位置已有同名的另存 `（初稿v2）`，不覆盖本人改过的文件。
4. 法条按 `AGENTS.md` 现查核验到"已核现行"再写；核不到的在稿里标【待核】。企业信息用可用的企业信息查询渠道核实。
5. 稿里有金额、面积、户数，且卷宗里有它依据的主文书（起诉状、判决、鉴定意见、合同）的，运行 `python 脚本\数字核对.py <新稿> <主文书> --base <主文书>`，第一、二部分逐条改或在稿末【内部备注】里说明（对外稿不留备注，改到一致为止）。
6. 出完运行 `python 脚本\改稿回流.py register <新稿路径> --rule 面板出稿`。

## 四、交付

1. 有待核、待客户确认事项的，在该文件夹写或更新当天的 `工作记录（YYYY-MM-DD）.md`。
2. 回执第一行："已出《<文件名>》：<完整路径>"；第二行起最多 3 行写稿子的要点和还缺什么。不发飞书，不交 notice。

## 不做的事

不发给本人以外的任何人，不向法院、客户提交；不删文件，不覆盖本人改过的文件；不改 台账 待办状态（本人看过稿再自己点完成）。
