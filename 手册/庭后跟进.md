# 庭后跟进手册

资料文件里 `events[].detail` 是 JSON，一场前三天内开过的庭：`date`、`time`、`hearing`（案件名或日程标题）、`case_id`（台账案件 id，可能为空）、`case_no`、`location`、`mediating`（是否标了调解中）。`answers` 是本人对上一轮卡片的回答。目标：开完庭，台账跟着更新，庭后要办的事进待办。

## 一、先问（answers 为空）

1. `python 脚本\ledger.py show <case_id>` 看案件现状；`case_id` 为空的用 `ledger.py find <当事人>` 找，找不到就在卡片正文注明"台账里没有这个案件"。
2. 先看有没有现成的答案，有就不问、直接走第二部分并在回执里写依据：卷宗里（`python 脚本\找案件目录.py`）有开庭日之后新增的笔录、调解书、传票、判决；或该案总任务、近三天 `日志\微信摘取\` 里本人已说过结果。
3. 没有现成答案的，交一张 `ask`：
   - 标题：`<月-日> <案件简称> 开庭结果`
   - 正文：一句"这场庭开完了，结果怎样？选一项，其余细节直接写在下面的回答框里（下次开庭时间、法庭要求几天内补交什么、调解方案）。"
   - 选项：`["还要再开庭", "当庭调解或庭后和解中", "审理终结，等判决", "这次没开成（改期或取消）"]`，不设推荐项；`mediating` 为真的把第二项放首位。
   - `key` 写 `after-<date>-<case_id 或案件简称>`。
4. 回执第一行"已问 <案件简称> 开庭结果"。

## 二、写回（answers 非空，或第一部分第 2 步已有答案）

按本人选的项和写的话办，没说到的不猜、不填：

| 结果 | 台账（`ledger.py`） | 待办（`add-task`，带 `case_key`） |
|---|---|---|
| 还要再开庭 | 说了下次时间的：`update <id> trial_date= trial_time=` 并 `add-schedule`；没说的：清空 `trial_date`、`trial_time`，另建待办"向法院确认下次开庭时间" | 法庭要求补交的材料、庭后代理词，各一条，期限按本人说的，没说期限的写"期限待确认" |
| 调解或和解中 | `mediate <id> on <一句说明>`；清空 `trial_date`、`trial_time`（另定了调解时间的按上一行写） | 协议定稿、客户确认、签署、领取调解书，本人提到的才建 |
| 审理终结，等判决 | 清空 `trial_date`、`trial_time`；`mediating` 为真的 `mediate <id> off` | "提交庭后代理词"（本人说不用交的不建）；"关注判决送达，收到后算上诉期" |
| 没开成 | 改期的写新时间并 `add-schedule`；取消的清空 | 需要重新准备的才建 |

1. 改为已结案须本人明确说"结案"，仍按 `ledger.py` 规则另交 `ask` 确认，不在这里直接改。
2. 本人回答里有金额、日期等关键内容的，原话记进案件：`update <id> notes=<原有 notes 加一行"[<开庭日> 庭后] 本人口述：……">`。
3. 回执第一行："<案件简称> 庭后已更新：<改了什么>；新建待办 N 条"。交一张 `notice`（加 `fyi`），正文逐条列改动。

## 不做的事

不替本人判断庭审结果；不向法院、客户、对方发任何东西；不删记录；不改卷宗文件；不出文书（要出稿的建待办，本人在面板点「出稿」）。
