# 微信交办转待办手册

目标：客户和同事在微信里交给本人或律所的事，一件不漏地变成案件台账里的待办；办完了自动关。全文中文。

## 步骤

1. 运行 `python 脚本\微信消息摘取.py`，读它打印路径的那份摘取（按会话排列，含本人和同事的回复，语音已转文字）。
2. 运行 `python 脚本\ledger.py tasks`，看现有未完成任务。
3. 逐个会话判断。**先把会话理清，再定待办**：
   - **一个会话里常有几件事交错，先按事项拆开。** 把会话里每条消息、每份材料（含开头"此前 7 天对方发来的材料"）分到各件事下，再逐件判断。例：某客户经办人的会话四天里有三件事：①她要某笔被扣划款项的法院票据，本人随后发了财务票据，已办；②某执行案的结案通知书，通知性质；③某监理公司的挂账，她先发了说明截图、明细账、收据，本人后来发企业查询截图说"这个公司还有啊"，她答"那就麻烦您发函吧"。
   - **指代按主体和内容认，不按时间远近认。** "发函""这个""那个案子""按你说的办"指的是哪件事，看紧挨着的上下文在谈哪家主体、哪笔钱、哪份材料（截图里是谁、文件里写的是谁），不是挨得最近的那份文件。认定依据写进描述。第一次曾把上例③的"麻烦您发函"错挂到结案通知书上，实际是依据明细账和收据向该监理公司发律师函，与执行案无关。
   - **材料读了内容再归属。** 文件和图片都打开看（图片直接看，docx 按下文抽正文，xlsx 读到末行看余额），按里面的主体、金额、事由归到对应事项；本人发的截图常是指代的关键，也要看。对不上任何事项的，在相关待办描述里单列"未归属材料"。不能只看最后一个文件。
   - **认不准就不猜。** 指向有两种以上可能的，待办标题写"向××确认……指哪件事"，描述列出各种可能和依据。
   - **对外发函类**（律师函、催告函、通知函）描述里写清：发函对象全称（以企业信息查询渠道核验的登记名为准，聊天里的截图只作线索）、依据哪几份材料、金额怎么来的、明显的风险（诉讼时效、债务主体、金额来源）。手写票据上的金额、账号只作线索，注明须核原件。
   - **已有待办发现判断错了的，改过来。** 本轮看到的上下文推翻了以前的判断（指向错、漏材料、主体错），运行 `python 脚本\ledger.py edit-task <id> %TMP%\claude_work\edit.json`（JSON 写 title、description，再加一句 note 说明改了什么、依据什么），并在第 6 步飞书里列出。
   - **算待办**：对方要我方做事、给意见、出文书、回复问题、查进度、提供材料、参加会议或开庭的，且在摘取范围内还没有办完。本人或同事回了"好的""收到""周一给你"不算办完；发出了文件、给出了实质答复才算。
   - **不算待办**：寒暄、通知类、对方自己要做的事、已当场答复完的、本人发给别人的东西。但下一条「约定日程」优先：答应了的事不是办完了，到那天要去。
   - **约定日程一律进台账日程，与是否算待办无关。** 会话里定了某个日期或时间要本人到场、发言、讲课、开会、开庭、仲裁、会见、带队、陪同的（含律协、专委会、行业协会、党派、工商联、其他律所邀请的论坛和活动，也含本人自己说出的安排，如"29号我搞个中巴陪你们转转"），只要本人答应了或没有拒绝，就运行 `python 脚本\ledger.py add-schedule %TMP%\claude_work\sched.json` 建日程（`schedule_type` 开庭、仲裁用"开庭"，其余用"其他"；钟点不明的 `schedule_time` 留空，描述写"下午，具体钟点待确认"）。描述首行写 `[微信待办]`，再写来源会话、时间和对方原话。同一场已有的脚本会跳过。
     - 先运行 `python 脚本\ledger.py agenda --days 400` 找原日程（输出里 `schedule` 后面那一项是日程 id）。
     - 改期、改时段、补地点的（"换到下午可以吗""下午可以""地点在律协三楼"），运行 `python 脚本\ledger.py edit-schedule <日程id> %TMP%\claude_work\sched_edit.json`（JSON 写要改的 `schedule_date`、`schedule_time`、`location` 等，加 `note` 写来源会话、时间、原话）；找不到原日程就按新时间建。
     - **活动取消、顺延未定期的**（"活动顺延到明年""这次不办了""取消了"），直接运行 `python 脚本\ledger.py cancel-schedule <日程id> 来源：私聊××，MM-DD HH:MM，原话"……"`，不要建"撤下日程""删除日程"之类的待办让本人去做。同一活动（`活动：` 行相同或描述指向这场）的准备待办，用 `done-task <id> 活动取消：<依据>` 一并关掉。对方说了新日期的，按新日期 `edit-schedule`；说"定了再邀请"的，不建新日程，也不建待办。第 6 步飞书里单列"取消日程几条"。起因：曾有同行告知一场论坛顺延到明年，中台当时没有取消日程的命令，建了一条待办让本人去撤，本人要求改为自动。
     - 开庭、仲裁的改期或取消，只认法院、仲裁委的通知或书记员、仲裁秘书的明确告知；客户或对方律师在微信里转述的，不改日程，建待办"向法院核实××案开庭是否改期"。
     - **开庭、仲裁的日程必须挂案件，标题用该案标准名称**（本人 2026-11-16 定的格式：`我方当事人简称与对方当事人简称XX纠纷（项目名称）`）。先 `ledger.py find <案号>`；台账里没有该案的，按 `手册\法院短信.md` 第一部分第 3 步「案件不在 台账」一条的字段先 `add-case` 建案，再建日程并在 JSON 里带 `case_id`、`case_name`。不要用"原告诉被告""××VS××"当日程标题（曾有一案只建了日程没建案，面板一直显示案号待补，标题也不合格式）。待办的 `case_key` 仍按"原告诉被告"写，它只是归并待办用的简称，面板显示时会换成台账里的标准名称。
     - 对方提了时间、本人还没回的，日程标题加"【待确认】"，另建待办"答复××（活动）是否参加"。
     - 本人明确拒绝的（"去不了""当天4个庭"），不建。
     - 需要准备的（发言、讲课课件、海报、带队名单、会前材料），另建待办，截止日写活动前几天。**准备待办与日程写同一行 `活动：<简称>`**，原"约见面"待办改写成会前准备的也要补；不写的面板会显示成两条并列（曾有一个非诉事项的日程与会前准备待办都没写活动行，非诉事务栏看着像重复）。
     - 例：某律师 11-02 邀请本人参加 12-26 下午某专委会的圆桌论坛，本人答"周六吧？应该可以"。此前按"已当场答复""社团活动"漏掉，两周后才回补。
   - 同一件事多条消息合成一条待办。
   - 摘取范围很宽（私聊全收、工作群全收）：家人朋友闲聊、兴趣社团（骑行、家长群、校友群）的活动、商业推销、课程营销一律不算。律协、专委会、统战、工商联、党派等社会职务交办的事（报材料、参会、提交名单、讲课、带队）算待办或日程，`client_name` 写该机构。
   - 发给本人的通知类消息里有截止时间、要本人报名或提交的，也算待办。
   - 待办描述逐件列出归到这件事的材料（时间、名称、一句话内容、路径）。
   - **客户或同事发来的文件一律算待办**（修改稿、反馈意见、证据、补充材料），本人回了"收到"也不算办完，不得只在别的待办里附一句。摘取里文件后面括号有本机路径：先打开读（docx 抽正文：有 litigation-doc-generator 的用它的 `dump_docx.py 文件 --out %TMP%\claude_work\x.txt`，没有的用 `pandoc 文件 -t plain -o %TMP%\claude_work\x.txt`），看清对方改了或提了什么，标题写成"审阅张三发回的质证意见修改备注并定稿"这类，描述里列对方意见要点（50 字以内）和文件路径。能对上案件的，用 `python 脚本\找案件目录.py <案号> <当事人简称>` 找卷宗，再判断放哪：先运行 `python 脚本\微信文件入卷.py suggest <本机路径> <卷宗目录>`，它按卷宗里已有的相近文件推荐目录（例如客户发回的质证意见修改稿，放到我方原稿所在的那一级）；没有相近文件的，按材料性质放进已有的对应子目录（证据放证据目录，鉴定材料放鉴定目录，往来函件放函件目录），拿不准就放卷宗根目录。**不得新建「微信收件」之类的收件目录。** 定了再运行 `python 脚本\微信文件入卷.py put <本机路径> <目标目录>`，描述里写它打印的路径。该案 7 天内有开庭或期限的，优先级高，截止日写开庭或期限前一天。"本机未下载"的，标题写"在微信里下载并审阅……"。
4. 新待办写进 台账：把下面字段写成 JSON 存到 `%TMP%\claude_work\task.json`，运行 `python 脚本\ledger.py add-task %TMP%\claude_work\task.json`（有相近的未完成任务会自动跳过）。
   - **一个案子只有一条总任务，下面挂分支。** 能对上具体案件的，`case_name` 照台账里该案的名称原样写（标准格式：我方简称与对方简称XX纠纷（项目名称）），JSON 里加 `case_key`（案子简称，写成"甲公司诉乙公司""丙置业诉丁公司"这样的"原告诉被告"）。先看第 2 步 `tasks` 输出里已有的 `case_key`，同一案子沿用同一个简称。带 `case_key` 的事项会挂到该案总任务下成为一个分支，没有总任务就自动新建；总任务的标题、截止日、优先级由脚本按未办分支重算，不要手改。律协交办、所务等对不上案件的，不写 `case_key`，照旧单独一条。
   - **不挂案件的待办和日程，说明里各写一行类别**（本人 2026-11-16 定，面板据此分栏）：`类别：行政`，即律协、专委会、党派团体、所务、讲课、论坛、比赛、接待参观等不是给客户办的法律事务；`类别：非诉`，即给客户办的不挂案件的法律事务（审阅材料、律师函、法律意见、咨询答复、调取材料）。**同一场活动的几项**（如讲课当天和次日的陪同参观、活动的报名与发言准备）另写同一行 `活动：<活动简称>`，待办和日程用同一个简称，面板会并成一组；先看已有待办、日程里有没有这场活动的简称，有就沿用。
   - `title`：动词开头，30 字以内，写清做什么，例如"答复某客户门店框架合同租金能否下调"。
   - `client_name`：对方所属单位（摘取里会话标题括号写了单位的照写），个人客户写姓名。
   - `case_name`：能对上具体案件的写案件名，先 `ledger.py find` 确认。
   - `assigned_to`：默认本人；对方点名某位同事、或同事已应承下来的，写该同事。
   - `due_date`：对方说了时间的按其换算成日期；说"尽快""今天"的写当天或次一个工作日；没说的写三个工作日后，并在描述里注"截止日为推定"（面板「今明两天」不列推定截止日的待办，本人 2026-11-17 定）。**本人已问、在等对方答复的事项**（如对方只说"律师函可能要改"、没说改哪里）不写截止日，描述里写"等××答复"，对方答复后再按答复定截止日（曾有一份律师函按推定截止日在面板显示"明到期"，本人指出）。
   - `priority`：涉及开庭、期限、付款、对外发函的为高，其余中。
   - `description`：首行 `[微信待办]`，再写来源会话、时间、对方原话要点（50 字以内）；内容来自语音转写的，注明"据语音转写，人名可能有误"。
   - 描述里的来源一律写成「来源：私聊<会话显示名>」或「来源：群：<群名>」，名字照摘取标题原样抄。中台的「微信材料收取」（每 30 分钟）按这一行和 `case_key`、`case_name` 推测该待办对应的微信会话和卷宗，自动绑定后把对方之后发来的材料收进卷宗；写不准就绑不上。你按第 3 步放进卷宗的文件，它会认出已在卷宗，不会重复复制。
   - **对上已有卷宗的，描述里另起一行写「卷宗：<完整路径>」**，非诉事项同样要写（用 `找案件目录.py <关键词>` 查，顾问单位的非诉卷宗也在里面）。材料收取见到这一行直接绑定，只收名字与卷宗文件相近或含 `case_key` 当事人的文件。没有 `case_name` 又不写这一行的待办，永远绑不上。例：客户转来某租赁合同纠纷后续谈判的备忘录，卷宗是 `<资料根目录>\<顾问单位目录>\<单位>\<事项>\后续谈判`，当时没写，材料没收。新事项没有卷宗的不写，不新建目录。
5. 已有的 `[微信待办]` 任务，摘取里能看到已办完的（发了文件、给了实质答复），运行 `python 脚本\ledger.py done-task <id> <依据一句话>`；案件总任务下的某个分支办完了，写 `done-task <总任务id>#<分支 no> <依据>`（no 见 `tasks` 输出的 `subtasks`），分支全部办完总任务自动完成。发现同一案子还有单独挂着的旧待办，运行 `python 脚本\ledger.py group-task <id> <案子简称>` 并进总任务。
6. 用 `python 脚本\飞书回复.py text` 给本人发一条：新增几条（逐条：截止日、交办人、事项）、新建日程几条（逐条：日期、事项、谁约的）、改期或取消日程几条（逐条：原日期、事项、依据）、自动关闭几条、改写几条（逐条：原判断、新判断、依据）、仍未完成且已过截止日的几条；最后一行列出本次看到的、纯属闲聊或推销且消息多的会话，建议加进仓库根目录的 `微信待办排除.json`（只建议，不自己改）。没有新增也没有变化的，第一行写"没事可做：无新交办"，不发飞书。
7. 回执第一行中文一句结论。

## 不做的事

不回任何人的微信，不替本人答复；不删 台账 任务；不把任务派给律所以外的人；不改微信收到的原文件，只复制。
