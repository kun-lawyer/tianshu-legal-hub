# 改稿回流手册

目标：中台出的稿被本人改过的，从改动里归纳出可复用的写作规则，经本人确认后写回手册或知识库，下次出稿不再犯。每周日 17:00 跑一次；`answers` 非空时是本人对上次候选规则的回答，直接走第三步。

## 一、取素材

运行 `python 脚本\改稿回流.py diff`。输出"没事可做"的，回执第一行照抄，结束。否则读它生成的 `改稿回流\素材-<日期>.md`。改动占比超过 60% 的稿，打开本人改后的版本通读一遍再判断（多半是重写，看结构和立场的变化，不逐句比）。

## 二、归纳与提问

1. 每处改动归一类：**删冗**（套话、重复论证、法条原文）、**改句**（长句拆短、换词、语气）、**结构**（增删论点、调顺序、标题）、**立场与判断**（让步、加强、换论证路径）、**事实与数字**（更正）、**格式**。
2. 只把**能用到下一份稿上的**归成规则：同类改动出现两处以上，或虽一处但明显是通例（如删掉所有"其一""其二"）。事实与数字的更正是个案，不成规则，只在报告里列出并查一句：是材料读错，还是材料本身有歧义。
3. 先查已有规则：`AGENTS.md`「通用工作约定」、`手册\` 下对应手册；如有自己的知识库，再查其中的写作规范和对应文书模板。已有规则而稿子没做到的，归为"**已有规则未执行**"，不另写新规则，说明是哪条、为什么没做到（检查脚本查不出、手册没提醒等），给出补救（如建议给出稿检查脚本加一项检查）。
4. 写 `改稿回流\<日期>.md`，1,500 字以内：
   - **概览**：表格（文件、出稿规则、改动占比、主要改动类型）。
   - **候选规则**：不超过 8 条，编号。每条：一句话规则；证据两处（原稿对改稿，各不超过 60 字）；写进哪里（具体文件和小节）；适用哪些文书。
   - **已有规则未执行**：条目、原因、补救。
   - **事实与数字更正**：逐条，注明原因判断。
5. 交一张 `ask`：标题"改稿回流：<N> 条候选规则"，正文逐条列编号和一句话规则，加报告路径；选项 `["全部采纳", "按我写的编号采纳", "都不采纳"]`，推荐第一项。没有候选规则、只有未执行或更正的，改交 `notice`（不加 fyi），然后运行 `python 脚本\改稿回流.py done`。

## 三、写回（answers 非空）

1. 按本人的回答取舍。写进哪里按报告里定的，每条规则一行到三行，带"（改稿回流 <日期>）"标记，放进该文件最贴切的小节，不另起"自动回流"大节；与已有规则冲突的，以本人的新改动为准，改旧条并注明。
2. 如有自己的知识库，写进知识库（文书模板、论证片段等）的按其现有格式写；知识库有自检脚本的写完跑一遍，通过或只有可解释的警告才算完。
3. 运行 `python 脚本\改稿回流.py done`。回执第一行写"采纳 N 条，已写入：<文件列表>"。

## 不做的事

不改卷宗里的任何文件；不改 skill 和知识库里的脚本（要改的写成建议放进报告）；本人没确认的规则不写回；不给本人以外的人发东西。
