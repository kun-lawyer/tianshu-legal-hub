# 新案到达自动成稿手册

资料文件里 `events[].detail` 是 JSON：`folder`（案件卷宗目录）、`case_no`、`court`、`role`（我方地位）、`docs`（已归档的法院文书和对方材料文件名），`answers` 是本人对之前卡片的回答。目标：本人第一次打开新案时，已有可以直接改的分析和初稿。全文中文，按 `AGENTS.md` 的约定（禁破折号、精炼；草稿阶段法条不核验，但对外定稿前须核）。

## 一、读材料

读 `folder` 里的起诉状或申请书、对方证据、传票、应诉通知书、举证通知书；扫描件先用 mineru-ocr 转。记下诉请、事实理由、对方证据清单、答辩期限和举证期限的起算与截止。

## 二、产出（都放进 `folder`，文件名带「（初稿）」）

1. **案件分析（初稿）.md**：按 case-analyzer 的 analyze 模式写，含：诉请与金额拆解、事实时间线（表格，每行注出处）、争议焦点、请求权基础与我方抗辩方向（每个方向写依据和需要的证据）、程序抗辩（管辖、主体、时效）、风险与建议。控制在 4 页以内。
2. **答辩状（初稿）.docx**：如有自己的知识库，先检索一次（客户、案由、立场、焦点合成一次查询），读前 3 至 5 项，命中的同类答辩状和论证片段要用上。有 litigation-doc-generator 的按它的答辩状母版直出（`--type answer`）；没有时用 python-docx 按法定答辩状格式出 docx，再用 gongwen-format 排版。答辩人、被答辩人信息按起诉状和企业信息写，查不到的留「【待补】」。
3. **证据与补充材料清单（初稿）.md**：我方需要的证据（对应每个抗辩方向）、找客户要的材料、对对方证据的初步质证要点。
4. 争议标的大、事实复杂的，另用 claim-chart 出要件对照表。
5. 诉请有金额的，答辩状与起诉状对一遍数：`python 脚本\数字核对.py <答辩状（初稿）.docx> <起诉状.docx> --base <起诉状.docx>`（起诉状是 PDF 的先转 docx 或跳过本步并在要点里注明），第一、二部分逐条改或在案件分析里说明。

## 三、写台账

`python 脚本\ledger.py find <案号>`；没有就 `add-case`（`case_name`、`court_case_no`、`court_name`、`client_name`、`opponent_name`、`case_procedure`、`cause`、`status`=已立案）。**案件名称一律用标准格式**（本人 2026-11-16 定）：`我方当事人简称与对方当事人简称XX纠纷`，建设工程等有项目的在后面加`（项目名称）`，没有不写；如"甲公司与乙电力建设工程施工合同纠纷（某道路高压线改造工程）""丙公司与丁置业房屋买卖合同纠纷"。案由、案号、法院照传票或受理通知书写，二审、再审用本审级案号，原审案号记进 `notes`。日程标题也用这个名称。答辩期限、举证期限写进 `evidence_deadline` 或在 `description` 里注明；开庭已排的按传票写 `trial_date`、`trial_time` 并 `add-schedule`。

## 四、交付

1. 先运行 `python 脚本\改稿回流.py register <各份初稿路径> --rule 新案成稿` 留底稿；再用 `python 脚本\飞书回复.py file <路径>` 把答辩状初稿和案件分析发给本人；再发一条 8 行以内的要点：案号法院、对方诉请、我方最有力的抗辩方向、答辩和举证截止日、最要紧的待补材料。
2. 交一张 `ask`：标题「新案：<案号>，要不要生成委托手续？」，选项 `["现在生成开案五件套", "暂不生成"]`，`about` 写卷宗路径。本人选生成的，下一轮按 case-intake-kit 在卷宗里生成（文书已下载，跳过下载步骤），完成后用飞书发文件。
3. 回执第一行中文一句结论。

## 不做的事

不向法院、客户、对方提交或发送任何东西；不删文件；不把案件标为已结案。
