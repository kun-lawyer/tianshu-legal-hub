# 开庭前作战包手册

资料文件里 `events[].detail` 是一场开庭（`date`、`time`、`hearing` 为案件台账里的案件名或日程标题）。目标：开庭前七天，在卷宗里备齐一套拿着就能上庭的「开庭材料」。全文中文，按 `AGENTS.md` 的写作约定（精炼、禁破折号、法条只写条号）。

**标准**（本人 2026-11-15 定）：本人一个真实案件第三次开庭的整套材料，文件构成、作战包的十四部分、篇幅和口吻都照它。开源版不附原件，只附虚构的骨架范例：作战包的内容文件范例是 `手册\作战包范例\甲公司诉乙公司第一次开庭_内容.py`，发问回答范例是同目录的 `甲公司诉乙公司第一次开庭_发问回答.json`。范例只示范十四部分的结构和写法，篇幅远短于实战；动笔前先读这两个文件，有自己的标准案件时替换成自己的。

## 一、找案件

1. `python 脚本\ledger.py find <当事人简称>` 查案号、审级、法院、对方；`python 脚本\找案件目录.py <案号> <当事人简称>` 找卷宗。
2. **只有定时派单的才查重。** 卷宗里（含各「…次开庭材料」子目录）实际查到（如 `Test-Path`）`庭前作战包（<日期>开庭）.docx` 的，第一行写"没事可做：已有作战包（<完整路径>）"结束。不得凭工作记录、飞书记录或印象认定"已有"：曾有一场开庭的作战包在工作记录里有、卷宗里已不在，两轮都以"已有"跳过，结果没有作战包。
   **本人在面板或飞书点名要出的**（事件 detail 里 `by` 为"面板"，或飞书里本人说要；定时派单的事件没有 `by`），不查重，照出；目标位置已有同名文件的另存为 `庭前作战包（<日期>开庭）（v2）.docx`，不覆盖。旧版不在标准的「…次开庭材料」目录里的，照新标准出全套。
3. 找不到卷宗的，交 `ask` 问卷宗在哪，选项列最可能的 2 至 3 个目录，外加"没有卷宗，只按台账出"。

## 二、读卷宗

1. 按时间倒序读：最近的法院文书（传票、举证通知、鉴定意见、上次庭审笔录）、对方的起诉状或答辩状及证据、我方已出的文书（答辩状、质证意见、代理词）、工作记录。扫描件没文字层的先用 mineru-ocr 转。
2. 上一次开庭的材料（「…次开庭材料」、应对方案、作战包）是本次的底稿，在它上面按新情况更新，不从零写。上次笔录里鉴定人、对方的原话要摘出来，作战包和发问清单都要用。
3. 运行 `python 脚本\ledger.py tasks` 看本案的案件总任务（标题【案子简称】开头）和其中未办的分支，分支里写了文件路径的必读：客户发回的修改意见要么吸收进定稿，要么在"庭前待办"里逐条点出，不得写"材料已备齐"。
4. 读的范围写进作战包末尾"附：材料来源与未核事项"。

## 三、交付件

**放在哪里，按审级自动判断**（本人 2026-11-15 定）：
1. 先判断这次开庭是哪个审级：法院是中院、高院而本案一审在基层法院的，案号含「民终」「行终」的，台账 的 `case_procedure` 写二审的，都是二审；含「再」的是再审。
2. 卷宗里有对应审级目录的（名含「二审」「再审」「一审」，如 `二审`、`02.二审（市中院）`），进这个目录；没有审级目录的，才放卷宗根目录。
3. 审级目录里已有专门的开庭准备子目录（名含「庭审准备」「开庭准备」，如 `04.二审庭审准备`），放进它下面；没有就直接放在审级目录下。
4. 子目录名 `<几>次开庭材料`，次数**只数本审级的开庭**：二审第一次开庭是 `一次开庭材料`，不把一审的开庭次数算进来。
5. 回执里写明为什么放这里（依据哪条）。例：某甲诉某村委会（二审，市中院）放 `16.某甲确认协议无效\二审\一次开庭材料\`；甲公司诉乙公司（二审，市中院）放 `079…\02.二审（市中院）\04.二审庭审准备\一次开庭材料\`。

文件名照标准：

| 文件 | 何时出 | 怎么出 |
|---|---|---|
| `庭前作战包（YYYY-MM-DD开庭）.docx` | 每场必出 | 第四、五节 |
| `对<对象>的质证意见（定稿）.docx` | 本次有新证据、鉴定意见要质证 | litigation-doc-generator `--type cross` 母版直出（没有该 skill 的按 `AGENTS.md` 替代做法，本表下同）。客户发回修改意见的，原稿和客户修改版都保留，另出定稿 |
| `代理词（庭审发言版）.docx` | 可能进入法庭辩论 | `--type agent-oral --against <同案答辩状>`，约 2,200 字（9 至 10 分钟），结论前置 |
| `询问<对象>问题清单（针对…）.docx` 及（带回答）（自己看）两版 | 要向鉴定人、证人或对方当事人发问 | 提交版用 `--type cross --title "询问鉴定人问题清单"` 母版直出，再跑 `脚本\发问清单三版.py` |

四份文件的核心数字（造价、欠款、各争议项金额）、焦点口径必须一致，以定稿质证意见（或本次的主文书）为准；作战包封面写"按《…（定稿）》口径"。

**数字核对（必做，不得以"已人工核对"代替）**：全部出完后运行 `python 脚本\数字核对.py "<…次开庭材料目录>" --base "<主文书>" --out %TMP%\claude_work\<案件>\数字核对.md`，读报告：
- 第一部分（同一项目不同数）、第二部分（疑似笔误）逐条处理：确是错的，改内容文件重出；不是错的（同名不同事、新旧口径对比），在作战包附录"材料来源与未核事项"里写一句为什么不同。
- 第三部分只作参考，扫一眼有没有主文书根本没有的新数字（是否该补进主文书或删掉）。
- 改完重跑，直到第一、二部分每条都已改或已说明。回执写"数字核对：N 条，已改 X 条，说明 Y 条"。

**发问清单的写法**：10 问左右，只问能引出我方有利答案的点；口语化，一问一个事实点，金额用万元；首段界定简称（如"补充稿""正式稿"）；落款日期右对齐。回答 JSON 每题写"建议回答：……"，答不利时的应对写"如答不利：……"，内部粗算写"参考（内部粗算……）：……"。**带回答版只放事实性的回答**，发问意图、内部数字、我方希望对方承认的结论一律标【仅自己看】（行首标整行，行中标后半句），见范例第 8、10 题。

## 四、作战包结构（照范例，十四部分加附录）

封面：标题、案件全称、第几次开庭及日期（带星期）时间、法院法庭（未核的标"待核"）、版本（日期、按哪份定稿口径）、承办人；"本次开庭的三句话口径"提示框（数字、认可与争议的范围、一句话打法）；目录。

1. **案件速览**：案号、法院法庭、审级程序、我方、对方（含代理人、经办人）、诉请、鉴定、本次重点；程序时间线表（日期、事件、意义）。
2. **庭审目标、底线与让步顺序**：主目标；不能失守的底线（三条左右）；让步顺序表（可让项目、对金额的影响），注明须客户确认后才可使用。
3. **数字底账**：我方主张的构成表（能逐项加回总数）；情景测算表（某项输了各是多少）；本次变动及我方态度表。数字用脚本算，不手算。
4. **争议焦点逐项攻防**：每个焦点写我方主张、关键证据（名称及卷宗内位置、页码）、鉴定人或对方原话、对方打法、薄弱点、备位、应对；另列"维持原意见的事项"。
5. **对方防线与拆解**：对方每条可能的抗辩（重新鉴定、付款条件、利息、违约金、质量等）配我方拆解；利息起算日等可退让的写成阶梯，按顺序主张。
6. **法官可能问什么**：表格（问、答、出示），8 至 12 问。
7. **发问要点**：三条铁律加表格（问、要点、想要的回答、答不利时），注明完整问法见自己看版。不发问的省略本节。
8. **庭审流程与分工**：表格（环节、法庭可能的动作、我方动作、主办、时长）。
9. **调解参考**：档位表（理想、目标、可接受、底线）及不可让的条件；底线须客户授权，未授权前不得对外表态。
10. **庭前待办与携带材料**：☐ 待办表（事项、时限、负责人）；携带原件清单。
11. **庭后四十八小时**：签阅笔录核对点、庭后代理词、跟进补正、给客户的庭审情况报告。
12. **软肋清单（仅限内部）**：表格（软肋、对方可能的用法、我方口径）。
13. **法条速查**：表格（法条、要点摘述、本案用途、核验状态）。注明"要点摘述，不是条文原文"。每条落 `AGENTS.md` 的五档核验状态并写核验日期和通道；沿用此前核验结果的写明当时日期，新引的现查，没核到的标"仅有候选"或"核验失败"。
14. **本院类案倾向**：用北大法宝或其他可用的案例库检索同院或同市中院近三年、与本案焦点相同的 2 至 4 件，表格（案号与日期结果、要旨、对我方，含可区分之处）；找不到写"未检到同院类案"，不凑数。

附：材料来源与未核事项（数字和策略各来自哪份材料；还没核的原件、数据）。

篇幅不设上限，标准为 18 页约 1.4 万字；但每节只写本案用得上的内容，没有的节写一句"本次不涉及"或省略。

## 五、出稿

1. 作战包内容照范例写成 `%TMP%\claude_work\<案件>\pack_content.py`（只调用 `h1` `h2` `para` `bullets` `table` `kv` `callout`，第一行写 `页眉 = '<案件简称及案由>'`），运行 `python 脚本\作战包排版.py "<卷宗>\<几>次开庭材料\庭前作战包（<日期>开庭）.docx" <内容.py>`。不要再跑 gongwen-format。
2. 质证意见、代理词、清单提交版有 litigation-doc-generator 的按其流程母版直出，体检报「严重」的改完再交；没有时用 python-docx 按法定格式出 docx，再用 gongwen-format 排版。
3. 回答写成 `%TMP%\claude_work\<案件>\answers.json`，运行 `python 脚本\发问清单三版.py <提交版.docx> <answers.json>`。
4. 子目录里已有本人改过的同名文件的，不覆盖：先抽回本人版正文（`dump_docx` 或 `pandoc -t plain`），在它上面改，另存为新版本并在回执里说明。

## 五之二、调解中的案件：出调解准备单，不出作战包

`detail.mode` 为"调解"，或 `hearing` 带「【调解中】」的（本人在面板点了「转调解」，或 `ledger.py mediate <id> on`），按本节办，第三至五节不做。

1. 查重照第一节第 2 步，查的是 `调解准备单（<日期>）.docx`。放哪里照第三节；已有作战包的放同一目录，作战包不改不删，调解不成时照用。
2. 必读：卷宗里最新的和解或调解协议稿（含本人发出稿与对方回改稿）、案件总任务里未办的分支（客户意见、对方态度、签署时间）、当天及前一天的工作记录、传票（被传事由是开庭、庭前会议还是调解）。
3. 准备单写成 `pack_content.py`，用 `作战包排版.py` 出 `调解准备单（YYYY-MM-DD）.docx`，3 页以内，五部分：
   1. **现状**：三句话，协议稿是哪一版、双方各自表态到哪一步、还差什么才能签。
   2. **条款核对表**：条款（金额、履行期限、利息、诉讼费负担、违约责任、以调解书结案或撤诉、账户信息、签署主体和日期）、现稿写法、我方底线、客户确认状态（已书面确认／口头／未问）。客户未确认的让步一律标红，不写成已定。
   3. **签署与到庭要件**：☐ 客户书面同意协议文本；☐ 授权委托书是否有调解、和解的特别授权，没有的补；☐ 盖章或法定代表人到场；☐ 对方收款账户核对；☐ 协议份数和随带的身份材料。调解结案受理费是否减半、由谁负担，按 `AGENTS.md` 现查后写，不凭记忆。
   4. **调解书要点**：请求法院写入调解书的条款，与协议逐条对应；协议约定"不出调解书则不生效"等条件的，写明理由。
   5. **调解不成的退路**：指向已有作战包的路径和仍然有效的部分；没有作战包的，一句话写出庭上主张要点，并在回执里提醒本人可在面板点「出作战包」。
4. 准备单里的金额、期限与协议稿对一遍：`python 脚本\数字核对.py <准备单.docx> <协议稿.docx> --base <协议稿.docx>`，处理方法同第三节。
5. 回执第一行写"调解准备单已出：<路径>"，另列还差客户确认的条款。

## 六、交付

1. **只放卷宗，不发飞书**（本人 2026-11-13 定）：不调 `飞书回复.py`，不交 notice。出完的每份文件运行 `python 脚本\改稿回流.py register <文件...> --rule 开庭作战包` 留底稿（本人改过后每周归纳成规则）。
2. 还有待核、待客户确认事项的，在卷宗根目录写或更新当天的 `工作记录（YYYY-MM-DD）.md`。
3. 回执第一行中文一句结论，写明「…次开庭材料」目录路径和其中各文件名（面板和晚报会显示这一句）。

## 不做的事

不改 台账（调解标记只由本人在面板或飞书里定），不给本人以外的人发任何东西，不删文件，不覆盖本人改过的文件。
